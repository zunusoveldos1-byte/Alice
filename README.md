# Alice Voice

## Локальное распознавание Vosk + Whisper

В «Настройки → Аудио / STT» можно выбрать «Vosk + Whisper — уточнение фраз».
Vosk сохраняет частичное распознавание и быстрые команды остановки;
Whisper уточняет полный запрос в отдельном потоке. Дополнительное время
обработки зависит от CPU. Аудио остаётся в RAM. Режим «Ярмарка» использует
прежний Vosk и проверку владельца.

Подготовка вручную (приложение ничего не скачивает при запуске):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-whisper.txt
.\.venv\Scripts\python.exe -c "from huggingface_hub import snapshot_download; snapshot_download('Systran/faster-whisper-small', local_dir='models/whisper-small', allow_patterns=['config.json','model.bin','tokenizer.json','vocabulary.txt'])"
```

Каталог `models/whisper-small` указывается в настройках. Отсутствие модели
или ошибка уточнения отображается явно; скрытой подмены текстом Vosk нет.
Для возврата к прежнему распознаванию выберите «Vosk — быстро».
Нативное сравнение без микрофона: `python scripts/qa_hybrid_stt.py`.

Режим «Ярмарка»: RNNoise, имя с ограниченным окном, удержание кнопки/Ctrl+F8,
проверка микрофона в RAM. [Использование и границы проверки](docs/fair-mode-validation.md).
При проверке владельца неизменный профиль голоса хранится в RAM;
смена или удаление файла учитываются при следующей проверке.
[Проверка кеша профиля](docs/owner-profile-cache-validation.md).
Для обычного разговора выключите «Ярмарку»: нажмите «ЯРМАРКА · Выключить»
в верхней строке или скажите «стоп ярмарка» / «ярмарка стоп».
В обычном режиме после включения микрофона имя и удержание кнопки не нужны.

Исправление повторной загрузки Silero и проверка единственной инициализации:
[отчёт диагностики](docs/silero-lifecycle-validation.md).

## Запуск

Python 3.11–3.13 x64, Windows 10/11, доступ к микрофону в настройках Windows.
В PowerShell из каталога проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m alice_voice
```

Если уже используется подготовленная в этой сессии `.venv`, достаточно
последней команды. При запуске микрофон выключен. Подготовьте модели,
проверьте настройки и нажмите центральную кнопку с микрофоном.

Главное окно использует PyQt6 и космическую тему: боковая навигация,
голосовой центр с анимированной сферой, страницы диалога и рабочей панели.
Переключатель «Голос / Работа» находится сверху боковой панели, настройки — снизу.
Страницы и мини-ассистент используют один VoiceSessionController; переходы
не перезапускают модель, микрофон или историю текущего сеанса.

Провайдер и модель выбираются в верхней строке; в узком окне имя модели
можно изменить через настройки. Озвучка и команды доступны в «Рабочей панели».
Сфера и волна используют сглаженный уровень микрофона и PCM текущей позиции
воспроизведения; при обработке запроса волна остаётся спокойной.
Громкость открывается наведением, фокусом или нажатием динамика и сохраняется.
Камера запускается только отдельной кнопкой, повторное нажатие освобождает
устройство. Меню «…» открывает анализ экрана, расшифровку, настройки и мини-окно.
«Рабочая панель → Облегчённое оформление» отключает декоративное движение.
Анимация сферы и волны обновляется отдельно от текста и кнопок. Подбор длины
последней реплики повторяется только при изменении текста, ширины, шрифта
или масштаба экрана. [Проверка нагрузки интерфейса](docs/ui-render-cache-validation.md).

Отчёт редизайна и ограничения проверок: [проверка интерфейса](docs/redesign/validation.md).
Снимки фактических Qt-виджетов создаёт `scripts/qa_cosmic_ui.py`.

Список индексов устройств без записи:

```powershell
.\.venv\Scripts\python.exe -m alice_voice --devices
```

В «Настройки → Аудио / STT → Микрофон» теперь доступны названия входов,
аудиоинтерфейс Windows (MME/DirectSound/WASAPI), номер и отметка системного
устройства. «Обновить» перечитывает список в фоне, без открытия микрофона.
Недоступный ранее выбранный вход не подменяется другим автоматически.

## Локальные модели — подготовка вручную

Приложение ничего не скачивает и не извлекает при запуске.

1. Возьмите стандартный `silero_vad.onnx` из
   [официального Silero](https://github.com/snakers4/silero-vad/tree/master/src/silero_vad/data).
   Нужна модель v5/v6 с входами `input`, `state`, `sr`; sequence-модель
   `silero_vad_16k_sequence.onnx` не подходит. Поместите файл в
   `models/silero_vad.onnx` либо задайте абсолютный путь в настройках.
2. Скачайте и распакуйте русскую
   [модель Vosk](https://alphacephei.com/vosk/models), например
   `vosk-model-small-ru-0.22`. Указывайте каталог, содержащий `am`, `conf`,
   `graph`, а не ZIP и не родительскую папку.
3. Для Vosk на Windows предпочтителен ASCII-путь, например
   `C:\VoiceModels\vosk-model-small-ru-0.22`. Если путь содержит кириллицу,
   приложение проверяет короткий путь NTFS; при отключённом 8.3 выдаёт
   понятное сообщение. Не включает 8.3 и не переносит модели самостоятельно.

Silero загружается из локального файла через `onnxruntime` (зависимость уже
включена); Torch и доступ к сети не нужны. Адаптер `alice_voice/vad.py`
принимает вызов `vad_model(audio_chunk, 16000)`: ровно 512 mono отсчётов
в виде PCM16 bytes либо NumPy int16 / нормализованного float32.
Кадры другой длины, включая 1532 отсчёта, отклоняются: стандартная модель
v5/v6 при 16 кГц поддерживает 512 отсчётов. Контекст из 64 отсчётов
адаптер добавляет самостоятельно и сохраняет между кадрами.
Порог `threshold=0.5` отделяет речь от тишины; `min_speech_ms=320`
требует десять кадров речи перед передачей кандидата в STT.
Начало фразы и преролл сохраняются, конец определяется `silence_ms=650`.

ONNX/Vosk загружаются в capture worker до открытия микрофона. Холодная
загрузка отображается отдельно в окне задержек.
Загруженная ONNX-сессия VAD и веса Vosk сохраняются в RAM между выключениями
микрофона. Каждый сеанс получает отдельное состояние VAD и новый распознаватель
Vosk. При изменении пути или файлов модели выполняется новая загрузка.
[Проверка повторного включения](docs/capture-model-cache-validation.md).

## LLM и голос

Точные короткие фразы «привет», «здравствуй», «здравствуйте», «доброе утро»,
«добрый день», «добрый вечер», «как дела», «спасибо», «большое спасибо» и
«благодарю» используют Fast-Path: готовый ответ сразу передаётся выбранному
синтезатору без генерации LLM. Фразы с продолжением, изображения и ожидающие
подтверждения обрабатываются обычным путём. [Проверки и замеры](docs/fast-path-validation.md).

Память владельца, подтверждения смены имени и просмотр фактов описаны в
[руководстве](docs/four-stages-guide.md#2-постоянная-память).
Результаты проверки [памяти](docs/owner-memory-validation.md) и
[диалога/задержек озвучки](docs/dialogue-continuity-validation.md) сохранены отдельно.

- **Ollama:** установите Ollama и вручную подготовьте текстовую модель
  (`ollama pull qwen3:4b`, пример). URL по умолчанию
  `http://127.0.0.1:11434`. В «Настройки → Модели и подключения → Модель Ollama»
  доступны `qwen3.5:4b` и `qwen3:1.7b`; можно также ввести своё имя модели.
  При открытии настроек список загружается из Ollama. Кнопка «Обновить» рядом
  с полем повторно получает установленные модели с указанного URL; текущий
  выбор сохраняется. Если сервер недоступен, остаются ранее показанные варианты.
  Эти модели есть и в быстром списке в шапке при выборе провайдера Ollama.
  Перед первым использованием установите выбранную модель командой
  `ollama pull qwen3.5:4b` или `ollama pull qwen3:1.7b`. Никаких инструментов
  управления компьютером. Доступность выбранной модели проверяется ответом
  `/api/chat` на каждый запрос. HTTP 404 предлагает выбрать установленную
  модель в настройках (`ollama list` покажет список). Ошибки соединения,
  таймаут и недоступность сервера показываются отдельно. Модель и провайдер
  автоматически не меняются. [Chat API](https://docs.ollama.com/api/chat).
- **Gemini:** выберите провайдер, задайте доступную вашему аккаунту модель
  и сохраните API-ключ в настройках. Ключ пишется только в Windows
  Credential Manager, не возвращается в поле, передаётся через заголовок
  `x-goog-api-key`. Проверка REST `models.get` выполняется перед первым
  запросом. Доступ к `gemini-2.5-flash` для новых пользователей ограничен;
  имя оставлено как пример, выберите доступную модель самостоятельно.
  [Модель](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash),
  [REST API](https://ai.google.dev/api/generate-content).
- **SAPI:** локальный установленный голос Windows. Пустое имя использует
  системный голос; для русского ответа установите русский голос и задайте
  точное описание. Синтез идёт через `SAPI.SpMemoryStream` в PCM
  22050 Гц, 16 бит, mono. Все COM-объекты принадлежат одному рабочему потоку.
  [SpMemoryStream.GetData](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms722572(v=vs.85)).
- **Silero — локально:** установите CPU-зависимость командой
  `.venv\Scripts\python.exe -m pip install -r requirements-silero.txt`, затем
  самостоятельно выберите движок в карточке озвучки или «Настройки → Голос».
  Поддерживаемая зафиксированная модель — `v4_ru`, русский язык, по умолчанию
  `xenia`, PCM16 mono 24000 Гц; доступны также aidar/baya/kseniya/eugene.
  Первое обращение загружает около 40 МБ официальных весов в
  `models/silero-tts/v4_ru.pt`. SHA-256 проверяется до загрузки пакета в PyTorch;
  незавершённый `.part` удаляется, повреждённый кэш даёт понятную ошибку.
  Затем сеть не требуется, модель переиспользуется в RAM между ответами и
  перезапусками служб. При запуске службы диалога выбранный Silero готовится
  в фоне параллельно с LLM: загрузка модели и два пробных синтеза без
  воспроизведения. Успешный прогрев сохраняется для модели и голоса в RAM;
  повторный запуск службы не повторяет его. Если обратиться сразу после
  включения, первый ответ ещё может ждать завершения подготовки.
  [Проверка прогрева и замеры](docs/silero-warmup-validation.md).
  Состояния загрузки при обработке запроса показываются в прежнем индикаторе.
  Синтез идёт в существующем executor, по умолчанию 2 потока CPU, без GPU.
  Длинный текст делится на последовательные фрагменты до 240 символов;
  каждый возвращает готовый PCM. Это **не нативный потоковый синтез**.
  WAV не создаются. Отмена немедленно очищает выход Alice; сам вызов
  `apply_tts` не прерывается внутри нативного вычисления, его результат
  отбрасывается, следующие фрагменты отменённого ответа не запускаются.
  Веса **CC BY-NC-SA 4.0**, не MIT: некоммерческое использование, атрибуция,
  сохранение лицензии; адаптации весов при распространении — ShareAlike.
  Для коммерческого использования необходимо отдельное разрешение.
  Подробности и измерения: [Silero TTS](docs/silero-tts-validation.md),
  [уведомления о лицензии](THIRD_PARTY_NOTICES.md).
- **Edge:** онлайн, по умолчанию `ru-RU-SvetlanaNeural`. `Communicate.stream()`
  передаёт сжатое аудио; оно собирается в RAM (не более 8 MiB), декодируется
  miniaudio в PCM 24000 Гц. Требуется интернет; API-ключ не требуется.
  [Edge-TTS](https://github.com/rany2/edge-tts),
  [miniaudio](https://github.com/irmen/pyminiaudio).
- **ElevenLabs:** выберите «ElevenLabs (онлайн)» в карточке «Модели и озвучка».
  В «Настройки → Голос» задайте ключ, `elevenlabs_voice_id`
  и `elevenlabs_model_id` (по умолчанию `eleven_multilingual_v2`). В JSON
  сохраняются только Voice ID и Model ID. Ключ хранится в Windows Credential
  Manager под именем `AliceVoice/ElevenLabsAPI`, тем же механизмом, что Gemini.
  Пустое поле ключа означает «не менять»; для замены введите новый ключ,
  для удаления отметьте «Удалить сохранённый ключ» и сохраните настройки.
  Отсутствие ключа обнаруживается до запроса к LLM; ошибка хранилища
  сообщается отдельно. Другой синтезатор автоматически не выбирается.
  Ключ передаётся только в заголовке `xi-api-key`. Провайдер асинхронно
  озвучивает фрагменты `SentenceChunker` по очереди через `/stream` и отдаёт
  PCM16 mono 24000 Гц пакетами 20–100 мс, не дожидаясь конца HTTP-ответа
  (последний пакет может быть короче), до 32 MiB на запрос. Его параметр `output_format='mp3_44100_128'`
  позволяет получать MP3 (до 8 MiB) и декодировать в PCM в рабочем потоке.
  Отмена, таймауты и ошибки API закрывают HTTP-ответ; повторных платных
  запросов при ошибках нет. Дополнительный SDK не нужен — используется `httpx`.
  [API синтеза ElevenLabs](https://elevenlabs.io/docs/api-reference/text-to-speech/convert).

При ошибке ни провайдер, ни модель, ни голос не переключаются.
Gemini отправляет текст текущей фразы и ограниченную историю; Edge и ElevenLabs отправляют
текст ответа. Локальные STT/VAD не передают аудио в облако. Постоянной памяти нет.
История хранится только до перезапуска службы или приложения.

## Screen Vision

В карточке «Управление ответом» нажмите «Посмотреть экран» либо скажите
«Посмотри на экран и объясни ошибку» при включённом микрофоне. Кнопка
работает и с выключенным микрофоном. Выберите Gemini и модель с поддержкой
изображений; для Ollama приложение предложит переключиться на Gemini.
Откроется превью с выбором источника: монитор, активное окно или область
монитора. Выберите источник и нажмите «Сделать снимок». Для активного окна
после нажатия есть три секунды, чтобы переключиться на нужное приложение.
В режиме области сначала сделайте снимок монитора, затем выделите мышью
прямоугольник на превью: приложение отдельно захватит выбранную область
с исходного экрана для сохранения деталей. Координаты учитывают масштаб
превью и мониторы с отрицательным смещением.

Проверьте снимок, при необходимости измените вопрос и нажмите
«Отправить в Gemini». Передаётся именно показанный JPEG без повторного
захвата. «Отмена» закрывает превью и освобождает изображение; поздний
результат фонового захвата после отмены игнорируется. Окна Alice временно
становятся прозрачными на время снимка, а для активного окна сворачиваются.
Пока открыто превью, новые речевые запросы не запускают диалог.
Во время другого ответа кнопка недоступна. «Стоп» отменяет анализ,
включая запрос, ожидающий запуска фоновых служб.

`alice_voice/utils/vision.py` захватывает выбранную область экрана через `mss`,
уменьшает изображение до 1280 × 1280 с сохранением пропорций без увеличения
и кодирует JPEG с качеством 75, максимум 2 MiB. MSS и Pillow установлены
как зависимости проекта. Захват и сжатие выполняются в рабочем потоке.
Снимок передаётся в текущий запрос Gemini вместе с текстом как
`inline_data` (`image/jpeg`, Base64); в историю диалога остаётся только текст.
До отправки можно повторять захват; в запрос попадает только последний
проверенный снимок. JPEG не сохраняется в истории диалога.
Снимки не сохраняются в файлы и не выводятся в логи. Настроенный API Gemini
получает содержимое экрана только при таком явном запросе.

## Фильтр оговорок

После финального результата Vosk обработчик STT применяет
`DisfluencyFilter` из `alice_voice/utils/disfluency_filter.py`. Он удаляет
отдельные слова-паразиты («эээ», «ммм», «ну», «короче», «как бы», «типа»)
и обрабатывает явные исправления: «ой нет», «точнее», «а хотя», «хотя нет», «забудь».
Соседние маркеры «ой нет, точнее» сохраняют исходное действие:
«Поставь таймер на семь... ой нет, точнее на восемь минут» →
«Поставь таймер на восемь минут». Сочетание «типа данных» сохраняется.
Хвосты «ну ты понял» и «ну вы поняли» удаляются в конце реплики;
цитаты и смысловые вопросы «ты понял?» сохраняются.
Например, «ну погода в Москве ой нет погода в Бишкеке»
превращается в «погода в Бишкеке». Исходная фраза и `clean_query` видны
в консоли как `stage=stt_query raw_query=... clean_query=...`; в LLM, историю
диалога и поле распознанного запроса попадает очищенный текст.

Фильтр не хранит состояние между репликами. Пустой результат, в том числе
«покажи погоду ой нет», не отправляется в LLM. Цитаты, «не забудь» и вопросы
«как бы ты…» сохраняются. Фильтр сохраняет намерение при замене фрагмента:
«поставь таймер на семь, точнее на восемь» → «поставь таймер на восемь»;
«напомни завтра купить молоко, точнее послезавтра» → «напомни послезавтра
купить молоко». Поддерживаются повторяющиеся предлоги, числа словами и
цифрами, даты, время и замена таймера на будильник. Несколько исправлений
применяются по очереди. Новая полная команда или «забудь» заменяет прежнюю
мысль. Это ограниченный набор правил, без общего понимания произвольной
речи: неоднозначное исправление оставляет только новый текст. Смысловые
употребления «данные типа int» и «сделай ответ короче» сохраняются.
Частичные результаты STT показываются без фильтра;
точные команды управления микрофоном проверяются по исходной фразе.

## Управление

Микрофон остаётся открытым между репликами, при LLM, синтезе и воспроизведении.
Он закрывается вручную, при точной фразе «Отключайся», «Выключи микрофон»,
«Отключи микрофон», при ошибке устройства и закрытии приложения.
Упоминание команды в предложении не отключает микрофон.

Тишина по умолчанию 650 мс, с округлением вверх до кадра: 672 мс.
Преролл 320 мс, максимум фразы 30 с; параметры редактируются.
Перед передачей в Vosk требуется минимум 320 мс кадров, которые Silero
считает речью: преролл и тишина в этот минимум не входят. Начало кандидата
буферизуется, поэтому подтверждение не обрезает начало слова. Короткие
шумовые фрагменты отбрасываются целиком. Настройка «Минимум речи, мс»
редактируется; 0 отключает фильтр. Порог Silero по умолчанию 0.5 —
вероятность речи, а не уровень громкости. Жёсткого отсечения тихой речи
по RMS нет. Состояние Silero сохраняется между обычными фразами; Vosk
сбрасывается перед каждой принятой фразой и после финализации.
Переполнение очереди из 32 кадров отбрасывает фразу и требует паузы перед
возобновлением распознавания. Оно не закрывает исправный микрофон.

Одновременно обрабатывается один ответ. Подтверждённая новая речь прерывает
его и после финализации становится следующим запросом; преролл и начало
фразы сохраняются. Голосовые «Стоп», «Замолчи», «Хватит» отменяют ответ,
сохраняя включённый микрофон. Команды проверяются по исходному STT-тексту,
до семантической очистки. «Отключайся» по-прежнему выключает микрофон.
«Остановить ответ» отменяет HTTP/синтез, очищает текущую фразу и останавливает
PCM. Отмена вызывает `QAudioSink.reset()`, освобождает QBuffer и PCM-очередь;
чанки и callback отменённых поколений отклоняются. Повторная отмена не
затрагивает уже начавшийся следующий ответ. Пауза вызывает
`QAudioSink.suspend()`, продолжение — `resume()` с тем же QBuffer.
Ответ LLM читается дельтами: Ollama использует `stream: true`, Gemini —
`streamGenerateContent`/SSE. Для SAPI и ElevenLabs первый пригодный фрагмент
может поступить в синтез до конца предложения: после запятой от 24 символов
или по границе слова от 56, с проверкой защищённых конструкций. Edge-TTS
получает законченное предложение. Десятичные числа,
распространённые сокращения и Markdown-ссылки не разрываются по точкам внутри.
Остаток без конечной пунктуации озвучивается после окончания потока.
Текстовая очередь ограничена двумя фрагментами; одновременно допускаются
три PCM, включая воспроизводимый, с общим лимитом 32 MiB. Каждый фрагмент
проигрывается последовательно. Пауза сохраняется и между фрагментами;
отмена очищает очередь и закрывает HTTP-поток. История обновляется только
после успешного воспроизведения всех фрагментов. Сетевой таймаут не
расходуется на ожидание освобождения очереди при паузе.

QBuffer проверяется и открывается `ReadOnly` до запуска QAudioSink.
Пакеты записываются в общий push-поток; один QAudioSink переиспользуется
при том же устройстве и формате, включая повторный запуск после reset.
Credits возвращаются по processedUSecs/исчерпанию выхода, а не при записи
байтов в устройство. IdleState внутри start не считается воспроизведением.
Поздние сигналы прежнего поколения игнорируются даже при том же QAudioSink.
HTTP-клиенты живут весь DialogRuntime; keep-alive ограничен 60 секундами.
Фоновый прогрев Ollama загружает только выбранную модель пустым запросом;
для Gemini проверяются метаданные и соединение, без запроса генерации.
Ошибка прогрева не меняет провайдера и не скрывает ошибку настоящего запроса.

Настройки можно менять во время работы. JSON записывается атомарно в
отдельном потоке; быстрые изменения объединяются. После успешной записи
смена модели, голоса или параметров захвата отменяет текущий ответ,
завершает прежние службы и восстанавливает прослушивание, если оно было
включено. GUI не ждёт потоков. Выключенный микрофон сам не включается;
ошибка записи не применяет несохранённые параметры. Громкость меняется без
перезапуска служб. Закрытие окна дожидается фоновых записей через сигналы.
Настройки лежат в `settings.json`, ключи Gemini и ElevenLabs — только в Windows
Credential Manager (`AliceVoice/GeminiAPI`, `AliceVoice/ElevenLabsAPI`). Они не
входят в Settings/to_dict, не подставляются в поля интерфейса и не попадают в
новые JSON-копии настроек. Заменить и удалить ключи можно в прежних вкладках
настроек. После попытки изменения ключа фоновые службы перезапускаются,
чтобы исключить использование прежнего кеша.

При первом чтении старого JSON непустой ключ ElevenLabs записывается в
Credential Manager и проверяется обратным чтением; только затем атомарно
удаляется открытое поле. Ошибка хранилища или записи JSON оставляет исходный
файл с ключом, показывает сообщение и останавливает запуск. Обычное сохранение
не может затереть неперенесённый ключ. Новые резервные копии исходного JSON
не создаются. Старые сторонние копии с открытым ключом автоматически не
обрабатываются. Не вставляйте ключи в промпт или URL.

Типы настроек проверяются строго: счётчики требуют целых чисел, логические
параметры — `true`/`false`; строки вместо чисел, `NaN` и бесконечности
отклоняются. Сохранение использует временный JSON в том же каталоге,
`flush`/`fsync` и атомарную замену. При ошибке записи прежний файл сохраняется.
Ошибки запуска фоновых служб отключают захват и показываются в окне;
закрытие ресурсов выполняется вне GUI. Консольные сообщения `stage=...`
показывают длительности загрузки моделей и готовность службы без текста речи
и значений ключей.

## Голосовое прерывание и защита от эха

Один VAD-триггер не прерывает ответ. CaptureWorker ждёт непустой частичный
STT-текст со стабильным первым словом не менее 100 мс либо финальный текст.
Только во время ответа короткие кандидаты допускаются в STT после 128 мс
речи (либо меньшего настроенного порога): короткое «Стоп» может не достигать
обычных 320 мс. Настроенное ожидание тишины не изменено.

С включённой настройкой «Наушники» подтверждённая STT-речь может прерывать
ответ и при воспроизведении. Эта настройка предполагает изолированный выход;
она не определяет физическое подключение наушников автоматически.

Для динамиков при пересечении с воспроизведением или его хвостом 250 мс
нужны дополнительные признаки: микрофонный PCM должен отличаться от текущего
выходного PCM, а текст — от ответа ассистента. Ограниченная RAM-ссылка
включает до трёх отрезков, приведённых к 2 кГц: до 60 секунд для полного
PCM SAPI/Edge, до 3 секунд недавней истории для потоковых пакетов;
соседние короткие пакеты объединяются, существенные паузы не сжимаются;
проверяется корреляция с задержкой эха до 500 мс и допуском времени 100 мс.
Неизвестная ссылка, тихий/короткий сигнал, корреляция или совпадение текста
блокируют прерывание. Преролл и непрерывность PCM при коротких VAD-паузах
сохраняются. Это эвристика, не AEC и не идентификация говорящего: реверберация,
искажения, сильное эхо поверх речи и ошибки STT могут давать пропуски или
ложные срабатывания. Реальная команда, повторяющая текст ассистента, может
быть подавлена. Ручная остановка доступна независимо от этой эвристики.

Проверки и границы измерения «голос → остановка» описаны в
[отчёте этапа 2](docs/stage2-barge-in-validation.md).

Edge-декодирование в miniaudio выполняется порциями в executor, проверяет
отмену и ограничение PCM перед добавлением каждой порции; нативный вызов
декодирования одной порции не прерывается посередине. Закрытие ждёт окончания
worker вне GUI. SAPI опрашивает отмену каждые 20 мс.
Отказ зависшего нативного драйвера/COM нельзя гарантированно исправить без
принудительного завершения; приложение не использует `terminate()`.

## Метрики и проверки

Кнопка «Задержки» показывает среднее/p50/p95 последних 512 измерений каждого
этапа через `perf_counter()`: очередь, VAD, тишина, STT, первый текст LLM,
полный ответ, первый фрагмент, LLM → первый PCM, первый PCM TTS, TTS каждого фрагмента,
готовый PCM → запуск выхода, конец речи → первый запуск выхода.
PCM → запуск включает ожидание ранее подготовленных фрагментов в очереди.
Длительность полного ответа LLM включает обратное давление очередей;
это не отдельное измерение времени вычисления на сервере.
Последняя метрика заканчивается на `QAudioSink.ActiveState`: физическое
появление звука в динамике отдельно не измеряется.
Аномалии логируются только как этап и длительность, без речевого содержимого.
Для диагностики STT в консоль также выводятся сырые частичные и финальные
результаты Vosk (`stage=stt_partial`, `stage=stt_final`, `text=...`),
RMS последнего переданного кадра в диапазоне 0–1 и периодические
`stage=audio_frame rms=... vad=... threshold=...`. Лог частичных результатов
ограничен десятью сообщениями в секунду, диагностический RMS/VAD — двумя.
Аудиофайлы и файлы логов приложение не создаёт.
Конвейер логирует `stage=llm_start`, `tts_start`, `pcm_ready` и
`first_playback` без содержимого ответа. Результаты его проверки —
в [docs/streaming-validation.md](docs/streaming-validation.md).

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m alice_voice --smoke
.\.venv\Scripts\python.exe scripts\hardware_check.py --check-input
.\.venv\Scripts\python.exe scripts\tts_check.py
```

Автоматические тесты используют поддельные микрофон/STT/HTTP и не читают
настоящие ключи. `test_vad.py` дополнительно проверяет настоящую локальную
Silero ONNX, если файл `models/silero_vad.onnx` подготовлен; иначе эти тесты
пропускаются. `--smoke` открывает и закрывает GUI без микрофона.
Отдельный `hardware_check.py --check-input` явно открывает стандартный
микрофон на 0.5 с, считает кадры в RAM и освобождает устройство; не выполняет
STT. Без этого флага скрипт только проверяет формат и перечисляет голоса.
Результаты реально проведённых проверок — в [docs/validation.md](docs/validation.md).

Для воспроизводимой установки после создания .venv можно использовать
`python -m pip install -r requirements.lock.txt` и затем
`python -m pip install -e . --no-deps`. Launcher: `powershell -File Start-Alice.ps1`.

### LM Studio

В настройках «Модель» доступны LM Studio, URL сервера (по умолчанию
`http://localhost:1234/v1`), ID модели и «Проверить подключение и модель».
Запустите Local Server в LM Studio, получите список и выберите фактический ID.
Проверка выполняется в фоне; выбранный провайдер и модель сами не меняются.
Если выбранный ID доступен, проверка дополнительно отправляет короткий запрос
с безвредным проверочным инструментом. Подтверждение этой пробы проверяет
формат tool calling, но не гарантирует правильность любых последующих действий.

Токен нужен только при включённой авторизации сервера. Введите его в поле
«Токен LM Studio» и сохраните настройки. Он записывается с проверкой чтения
в Windows Credential Manager (`AliceVoice/LMStudioToken`), не в JSON.
Пустое поле сохраняет прежний токен; флажок удаляет его. Ошибка хранилища
не приводит к отправке анонимного запроса. Для внешнего сервера используйте HTTPS.

Ответы поступают через `/v1/chat/completions` по SSE, с общим HTTP-пулом,
таймаутами и закрытием запроса при отмене. В озвучку передаётся только
`delta.content` после удаления явных блоков reasoning. Отдельные поля
reasoning/thinking игнорируются. Исходное семейство Qwen3 получает `/no_think`;
для остальных моделей отключайте thinking в LM Studio, если это поддерживается.
Произвольные непомеченные рассуждения внутри обычного `content` невозможно
надёжно отличить от ответа; для голосового режима выбирайте подходящую модель
и проверьте её серверный шаблон. Анализ экрана сохраняет прежний предпросмотр
и ограничение Gemini.

Адаптер поддерживает явный список `Tool` через `LLMProvider(..., tools=...)`:
только зарегистрированные имена, полная сборка аргументов, ограниченный JSON,
проверка типов/обязательных полей и отказ от лишних аргументов до выполнения.
Допустима ограниченная схема JSON Schema: object/array/string/integer/number/
boolean/null, properties, required, items, enum, minimum, maximum, maxLength,
description, additionalProperties (лишние поля всегда запрещены).
Обработчики асинхронные и должны поддерживать отмену. Исполняемого реестра
инструментов в текущей Alice нет; действия с компьютером автоматически
не регистрируются и предпросмотр экрана через tool calling не обходится.

Результаты и ограничения проверки: [docs/lmstudio-validation.md](docs/lmstudio-validation.md).
Скрипт реального замера (не меняет настройки; вывод с нулевой громкостью):

```powershell
.\.venv\Scripts\python.exe scripts\qa_lmstudio.py --model "фактический-ID-из-списка"
```

Он измеряет один запуск с новым клиентом и 20 повторов одинакового запроса:
HTTP-запрос → первый видимый текст, отправка текста → первый PCM и ActiveState.
После первого ActiveState ответ отменяется. Холодную загрузку модели и
акустическое появление звука этот скрипт не подтверждает.
