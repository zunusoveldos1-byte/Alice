# Этап 4: задержка и потоковый PCM

Дата проверки: 21 октября 2026. Изменён только этап 4. Интерфейс, выбранные
провайдеры, пользовательские настройки и поведение этапов 1–3 сохранены.
Цель «фактический первый звук менее 1500 мс» **не подтверждена**.

## Изменения

- ElevenLabs PCM использует HTTP `/stream`: выравнивание PCM16, пакеты
  20–100 мс (остаток может быть короче), ограничение 32 MiB на ответ.
  Первый пакет передаётся в GUI до окончания HTTP-ответа. MP3 сохраняет
  полное декодирование в executor; SDK и новые зависимости не добавлены.
- SAPI и ElevenLabs получают первый пригодный текстовый фрагмент до точки:
  запятая/двоеточие/точка с запятой после 24 символов или граница слова после
  56. Проверяются числа, ссылки, код и незаконченные предлоги. SAPI по-прежнему
  возвращает PCM целого фрагмента; Edge-TTS ждёт предложения.
- Один QAudioSink и push-поток переиспользуются для того же устройства и
  формата. Следующие PCM заранее записываются без перезапуска потока.
  Credits возвращаются после обработки/исчерпания выхода, а не после write.
  Пауза сохраняет байты; отмена делает reset, очищает очереди и буферы.
  Проверки токенов и поколения callback защищают от поздних пакетов и сигналов
  даже при повторном использовании того же объекта QAudioSink.
- Короткие пакеты объединяются в эталон эха: до 3 секунд недавней потоковой
  истории; полный клип SAPI/Edge сохраняет начало, до 60 секунд. Существенные
  разрывы остаются отдельными; исчезнувшая из истории запись даёт unknown.
  Это прежняя консервативная эвристика, без AEC/идентификации говорящего.
- HTTP-клиенты живут весь DialogRuntime: до 4 соединений, 2 keep-alive,
  срок keep-alive 60 секунд. Фоновый прогрев имеет лимит 5 секунд и отменяется
  при завершении. Ollama: пустой `/api/generate` выбранной модели, keep_alive
  5m. Gemini: метаданные выбранной модели и TLS, без платной генерации и без
  утверждения о прогреве весов облачной модели. Переключения провайдера нет.
- Добавлены отдельные метрики TTS → первый PCM и прогрева; прежний ключ
  llm_first_sentence теперь обозначает первый пригодный фрагмент.

## Ожидание тишины: 250–350 мс не включено

Проверены 4 русские фразы, 6 внутренних пауз (160, 256, 320, 384, 512,
600 мс), одинаковый PCM для каждой политики: реальный SAPI Irina → Silero →
Vosk → PhraseSegmenter. Голос синтетический, части фраз соединены с паузами;
это не корпус живых дикторов. «Обрезание» здесь — преждевременная отправка
части запроса/деление на два запроса, даже если оставшиеся слова позднее распознаны.

| Политика | Преждевременное деление / 24 |
|---|---:|
| 250 мс | 18 |
| 300 мс | 14 |
| 350 мс | 12 |
| адаптивная 250–350 мс | 12 |
| контроль 650 мс | 0 |

Экспериментальная адаптация выбирает 250 мс после распознанного окончания
с единицей времени/числом, иначе 350 мс. Этого недостаточно для сохранения
всех фраз. Пользовательские 650 мс оставлены без изменения. Регрессия проверяет
целостность PCM при внутренних паузах 160–608 мс. Паузы произвольной длины
этот механизм гарантированно не отличает от конца запроса.
Данные: [stage4-endpoint-results.json](stage4-endpoint-results.json).

## Границы реальных измерений

В пользовательской конфигурации выбраны Gemini gemini-2.5-flash и ElevenLabs.
Ключ ElevenLabs отсутствует; у доступного сервера Ollama нет установленных
моделей. Поэтому облачный E2E с выбранным TTS и реальный прогрев весов Ollama
измерить нельзя. Приложение сохраняет понятную ошибку, настройки не меняются.

Для диагностики явно переопределён TTS на SAPI Irina только внутри стенда:
громкость 0, режим наушников, история 0, max_tokens 64, max_response_chars 200.
Четыре одинаковых русских запроса повторяются пять раз; холодная попытка
измеряется отдельно. Замороженная копия stage3 сравнивается с текущим кодом.
PCM создаётся один раз в родительском процессе и передаётся обоим дочерним
процессам через stdin, только в RAM. Конфигурация и PCM проверяются SHA256.
VAD/STT работают в реальном времени; микрофон заменён повтором входного PCM.

Попытка реального Gemini дала 10 успешных тёплых запусков из 20 на исходной
версии; затем HTTP 429 с суточной квотой 20 запросов на модель. Пауза между
запросами это ограничение не снимает; повторы прекращены. 6/20 попыток (30%)
оказались быстрее 1500 мс до ActiveState. Это неполная исходная серия, без
парной облачной серии «после»; по ней нельзя заявлять ускорение или SLO.
Среди 10 успешных тёплых попыток медиана / p95 конца речи → ActiveState:
1433,6 / 1645,8 мс; первый текст Gemini: 491,7 / 739,3 мс. Ошибочные попытки
не включены в эти процентили, но входят в знаменатель доли быстрее цели.
Данные: [stage4-before-results.json](stage4-before-results.json),
[stage4-provider-limit.json](stage4-provider-limit.json).

Три дополнительных **реальных** GET метаданных Gemini получили HTTP 200:
569 / 156 / 166 мс, TCP-подключения 1 / 0 / 0, TLS-handshake 1 / 0 / 0.
Это подтверждает переиспользование соединения, не доступность генерации после
исчерпания квоты. Запросов генерации в этой проверке нет.
[stage4-connections-results.json](stage4-connections-results.json).

прогона. В каждой ячейке медиана / p95, мс; p95 — линейная интерполяция
95-го процентиля по 20 наблюдениям. Ошибки: 0 / 0.

\* В исходной версии SAPI возвращает один полный PCM; использован TTS целого

STT обрабатывает кадры уже во время речи; таблица показывает финализацию,
а не сумму всех вызовов Vosk. Endpoint измерен от последнего VAD-voiced кадра,

Медианы этапов не складываются в медиану полного пути.

Выигрыш медианы короткого ответа — лишь 5,5 мс (0,5%), p95 — 35,9 мс.
Такую разницу нельзя считать убедительным общим ускорением без повторных
серий: вариации SAPI/планировщика сопоставимы с эффектом.
Холодная попытка, **n=1** на версию, отдельно:

| Показатель, мс | До | После |
|---|---:|---:|
| Конец исходной речи → ActiveState | 1429,6 | 1346,7 |
| Загрузка Silero | 334,5 | 517,4 |
| Загрузка Vosk | 1484,3 | 1615,0 |
| От создания контроллера до ActiveState, включая воспроизведение входного запроса | 5655,2 | 5882,7 |

Это холодный запуск процесса, не гарантия пустого системного файлового кэша.
Для n=1 медиана/p95 не дают распределения и не вычисляются.
Сырые данные: [до](stage4-native_before-results.json),
[после](stage4-native_after-results.json).
SHA256 конфигурации, входного PCM, запросы и распознанный текст совпадают
во всех 21 парах обеих контролируемых серий; фоновые службы завершились.

В короткой серии HTTP LLM заменён фиксированным transport: первый SSE через
300 мс, одинаковый ответ Four. для всех запросов. Vosk, Silero, SAPI, GUI-цикл
и QAudioSink настоящие. Следовательно, серия показывает накладные расходы
локального конвейера с фиксированным LLM, а не скорость облачного сервиса
или выигрыш потокового ElevenLabs. За счёт короткого ответа она также не
измеряет выигрыш разбиения длинной фразы до конца предложения.

## Регрессии и реальный аудиобэкенд

Автотесты используют моки HTTP и QAudioSink: первый PCM до HTTP-tail,
целостность/выравнивание байтов, закрытие потока, отмена, поздние чанки,
повторная отмена, pause/resume, непрерывная очередь, reuse объекта выхода,
устаревшие callback, отсутствие старта/завершения по начальному IdleState,
сохранение слов, чисел/ссылок/кода, пауз и evidence эха коротких пакетов.
Проверен warmup выбранной модели без fallback, в том числе 404 Ollama.

Отдельный прогон реального SAPI/Silero/Vosk/QAudioSink с беззвучным выходом:
8/8 пользовательских команд/запросов прервали ответ; 2/2 воспроизведения
собственных команд не вызвали прерывание. Оба режима политики проверены,
но физические наушники/динамики и живой микрофон не тестировались. Runtime
LLM/TTS в этой проверке — тестовый; PCM заранее создан настоящим SAPI.
«Стоп»: начало исходного голосового PCM → StoppedState 808 мс (наушники),
769 мс (динамики), по одному запуску; это не время cancel_response и не
акустическая остановка. Начало следующей фразы сохраняется.
[stage4-interruption-results.json](stage4-interruption-results.json).

Ещё одна проверка **настоящего QAudioSink без HTTP-моков**: 20 пакетов по
100 мс, 24 кГц PCM16 mono, весь поток обработан за 2105 мс, ошибок нет.
Получены 20 завершений пакетов; 21-й сигнал старта относится к следующему
клипу, немедленно отменённому в проверке reset. Объект выхода повторно
использован, повторная отмена оставила StoppedState и пустой буфер;
добавление в остановленный поток отклонено. Тестовый PCM — тишина,
громкость 0: это проверка очереди/нативного бэкенда, без оценки слышимого звука.
[stage4-pcm-output-results.json](stage4-pcm-output-results.json),
`scripts/qa_stage4_pcm_output.py`.

Финальный полный набор: **216 тестов, OK, 33,989 с**. GUI `--smoke`:
**exit 0**, без микрофона. Тесты этапов 1–3 остаются в полном наборе.
Команды: `.venv/Scripts/python.exe -m unittest discover -s tests -v` и
`.venv/Scripts/python.exe -m alice_voice --smoke`.

Методика реализована в `scripts/qa_stage4_latency.py`, `qa_endpoint_sweep.py`,
`qa_stage4_connections.py` и `qa_voice_interruptions.py`. HTTP-фикстуры не
доказывают доступность облачного TTS. API потока сверено с официальной
[документацией ElevenLabs](https://elevenlabs.io/docs/api-reference/text-to-speech/stream).
Границы processedUSecs/reset — с [документацией Qt](https://doc.qt.io/qt-6/qaudiosink.html#processedUSecs).

## Оставшиеся узкие места

650 мс endpoint остаются главным управляемым расходом: уменьшение без
дополнительного распознавания конца высказывания делит запросы. Облачные
TTFT/квота, первый PCM реального ElevenLabs и акустическая задержка остаются
неизмеренными в парной серии. SAPI/Edge сохраняют синтез полного фрагмента;
для MP3 требуется декодирование целого ответа. Холодная загрузка Vosk/VAD и
открытие нативного аудиовыхода измеряются отдельно. Потоковый HTTP с моками
доказывает корректность ранней подачи, но не её реальную сетевую задержку.

Для окончательной приёмки нужны настроенный ElevenLabs и доступная квота LLM,
20+20 запусков того же набора на обоих вариантах с акустическим loopback.
