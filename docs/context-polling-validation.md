# Сокращение фоновых запросов окна — 30 октября 2026

Раньше фоновая задача каждые 0,5 с вызывала `observe_context`, получая заголовок,
PID, путь процесса и координаты активного окна. Чтение пути требует открытия
дескриптора процесса. Это повторялось даже при неизменном окне.

Теперь фоновая задача вызывает `poll_context`. Она проверяет только HWND
через `GetForegroundWindow` с прежним периодом 0,5 с. Полное наблюдение
выполняется при смене HWND или через пять секунд после последнего фонового
чтения. Периодическое обновление сохраняет актуальность заголовка и координат,
которые могут измениться без смены HWND. Ошибки чтения не создают поток
повторных полных запросов каждые полсекунды: при неизменном HWND повтор
происходит через пять секунд. При недоступности лёгкой проверки остаётся
периодическое полное наблюдение.

Наблюдения сериализованы RLock, поэтому фоновая и командная задачи не меняют
контекст одновременно. `observe_context` всегда читает Windows заново;
проверки внутри обработки и выполнения команд не кешируются. Если окно
сменилось, действие, привязанное к прежнему HWND, не отправляется. Неудачное
чтение текущего окна возвращает пустой результат, а не сохранённый контекст.
Последнее внешнее окно по-прежнему хранится только как справочная история.

Это оптимизация полных запросов метаданных, не событийная подписка Windows:
лёгкий опрос раз в полсекунды сохранён. Очень короткое переключение между
проверками, как и раньше, может не попасть в фоновую историю. Изменение
заголовка/координат того же окна в фоне может отразиться с задержкой до пяти
секунд; выполнение команды использует свежую проверку.

## Проверка количества запросов

`scripts/qa_context_polling.py` воспроизводит 120 проверок за условные 60 с
с управляемыми часами и локальным fake backend. Настоящие окна не читаются,
действия не выполняются. Исходный сценарий вызывает прежний `observe_context`
каждый такт, оптимизированный — новый `poll_context`.

| Сценарий | Полных запросов до | После | Лёгких проверок после |
|---|---:|---:|---:|
| Одно окно всю минуту | 120 | 12 | 120 |
| Переключение каждые 2 секунды | 120 | 30 | 120 |

Для неизменного окна полных запросов стало на 90% меньше. Это детерминированная
проверка числа обращений, не измерение CPU или полной задержки команд. При
частых переключениях выигрыш меньше; свежие командные проверки добавляются
отдельно и не учитываются в этих фоновых сценариях.

Данные: [результат сценариев](context-polling-results.json).

```powershell
.\.venv\Scripts\python.exe scripts\qa_context_polling.py
```

## Проверки

Полный набор `python -m unittest discover -s tests -v`: **457 тестов, OK,
74,306 с**. Синтаксис изменённых Python-файлов проверен через `compileall`.

Новые тесты покрывают неизменное окно, переключение, обновление заголовка
без смены HWND, ошибки метаданных, отказ лёгкой проверки, выбор нового метода
фоновой задачей и безусловную перепроверку перед командой. Существующие
проверки смены фокуса и защиты от устаревшего контекста также пройдены.

Дополнительно выполнена проверка настоящего Windows backend: получение HWND
успешно, два немедленных фоновых опроса вызвали одно полное чтение. Названия
окон, пути процессов и содержимое экрана в отчёт не выводились.
