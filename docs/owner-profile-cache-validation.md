# Кеш профиля владельца — 30 октября 2026

`OwnerVerifier` проверяет длинную фразу перекрывающимися окнами: до изменения
каждое сравнение заново читало `owner.json`, разбирало JSON и нормализовало
вектор профиля. Теперь экземпляр `OwnerProfile` хранит один нормализованный
профиль в RAM. Перед каждым обращением проверяются путь, идентификатор файла,
размер, mtime и ctime. Проверка метаданных сохраняется на каждом окне аудио:
оптимизируется чтение содержимого, а не все обращения к файловой системе.

Изменение метаданных сбрасывает кеш. Повторная регистрация на том же объекте
явно сбрасывает его после успешной атомарной замены файла. Регистрация через
другой объект обнаруживается по метаданным, включая замену файла с тем же
размером и mtime. Удаление, повреждение и ошибка доступа возвращают отказ,
а не устаревший профиль. После первого чтения метаданные проверяются повторно:
изменённый во время чтения профиль не публикуется.

RLock сериализует обращения к кешу и атомарную публикацию регистрации на одном
объекте. `load()` возвращает копию вектора, чтобы вызывающий код не мог изменить
сохранённую в RAM идентичность. Отмена до публикации сохраняет старый профиль.
Аудиозаписи в кеш не входят. Порог голоса, режим активации и выбранный микрофон
не изменялись. Эта оптимизация действует там, где уже используется проверка
владельца; она не включает её в других режимах автоматически.

## Проверка чтений и времени

`scripts/qa_owner_profile_cache.py` использует временный файл и искусственный
вектор из 192 значений. Настоящий профиль пользователя, микрофон, speaker model,
аудиозаписи и сеть не используются. Baseline воспроизводит прежнюю реализацию
`load` без кеша. Сравнения в обеих сериях дают одинаковый результат.

| Сценарий | Чтений содержимого до | После | Время до / после |
|---|---:|---:|---:|
| 29 сравнений — окна 30-секундной фразы | 29 | 1 | 19,6 / 4,6 мс |
| 1000 повторных сравнений | 1000 | 1 | 326,9 / 119,6 мс |

Это один диагностический прогон работы с профилем. Нейросетевой расчёт
аудиопризнаков, полная проверка голоса и задержка ответа не измерялись.
Процессорное время короткой серии округлилось до нуля из-за дискретности
счётчика; оно не используется для оценки выигрыша. На длинной серии
process_time составил 328,1 / 93,8 мс, но это не процент CPU приложения.

Данные: [результаты](owner-profile-cache-results.json).

```powershell
.\.venv\Scripts\python.exe scripts\qa_owner_profile_cache.py
```

## Проверки

Полный набор `python -m unittest discover -s tests -v`: **466 тестов, OK,
58,516 с**.

Новые тесты проверяют единственное чтение для окон длинной фразы, независимые
копии векторов, повторную регистрацию через другой объект, удаление,
повреждение, атомарную замену с сохранением размера и mtime, удаление во время
чтения, параллельные загрузки, ошибку доступа и отменённую регистрацию.
Существующие проверки несовпадающего голоса, тишины и чужого начала фразы
также пройдены. Синтаксис изменённых Python-файлов проверен через `compileall`.
