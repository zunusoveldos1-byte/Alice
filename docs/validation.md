# Реальные проверки — 14 октября 2026

Среда: Windows x64, Python 3.12.14, PyQt6 6.11.0 / Qt 6.11.2,
sounddevice 0.5.6, Vosk 0.3.45, ONNX Runtime 1.31.0, miniaudio 1.71.
Точные зависимости сохранены в `requirements.lock.txt`.

## Выполнено

- `python -m unittest discover -s tests -v`: **33 теста, 0 ошибок**,
  финальный запуск 0.642 с. Тесты не используют настоящие ключи, облако,
  аудиофайлы или реальный микрофон.
- `python -m alice_voice --smoke`: окно PyQt6 открывается и корректно
  закрывается, exit code 0; микрофон выключен.
- `python -m pip check`: No broken requirements found.
- `python scripts/hardware_check.py --check-input`: стандартное устройство
  PortAudio №1, Realtek microphone array, поддерживает PCM16/16000/mono.
  Получено **15 кадров по 512 отсчётов**, переполнения нет; поток закрыт.
  Захват 0.5 с; включая открытие/закрытие команда заняла 773.7 мс.
  Это длительность аппаратной проверки, **не задержка голосового ответа**.
- `python scripts/tts_check.py`: три нативных синтеза с голосом
  **Microsoft Irina Desktop — Russian** через SpMemoryStream, PCM
  22050 Гц / 16 бит / mono, последний буфер 132696 байт. Стандартный
  выход Qt: Realtek speakers. Громкость проверки 0: подтверждена работа
  нативного выхода, но слышимое качество не оценивалось.
  Все три воспроизведения завершились, пауза сохранила позицию QBuffer,
  поток COM закрылся. Exit code 0.

## Измеренные задержки нативного SAPI/Qt (N = 3)

| Этап | Среднее, мс | p50, мс | p95, мс |
|---|---:|---:|---:|
| Полная подготовка SAPI PCM | 123.0 | 77.8 | 202.2 |
| Готовый PCM → QAudioSink ActiveState | 858.0 | 116.8 | 2122.3 |

Фраза в диагностике: «Проверка голосового ответа.». В первую пробу включена
холодная инициализация Qt-аудиовыхода: около **2345 мс**. Малое N делает p95
ориентировочным; это не репрезентативный бенчмарк. Физическую задержку звука
не измеряли. Пауза 150 мс добавлена после старта первого воспроизведения и
не включена в измерение подготовки/старта.

В первой версии диагностического скрипта пауза вызывалась внутри сигнала
ActiveState до возврата start(); позиция тогда продолжала двигаться.
Исправлена диагностика: пауза вызывается очередным GUI-событием после
возврата start(), как при реальном нажатии. Повторная проверка прошла.

## Автономное покрытие

PCM-контракт и короткий callback; queue32 и overflow; исходные байты Vosk;
сбор сегментов; преролл, включая округление; завершение по тишине; открытый
микрофон между фразами; одно активное обращение и дедупликация; точные
стоп-команды; отмена до ответа сервера; поздние ответы и queued фразы;
повреждение во время финализации; пауза с тем же QBuffer; echo intervals/tail;
bounded Edge buffers/decode; HTTP streaming/model availability/header key;
безопасные ошибки; mock Credential Manager; изоляция recurrent Silero-state
и переиспользование CPU ONNX-session; отсутствие аудиофайлов; завершение
capture/dialog workers; однократное асинхронное применение настроек.

Независимое ревью нашло две гонки и два ограничения буферизации/преролла.
Для них воспроизведены failing tests, исправления проверены полным набором.
COM-локальные ссылки освобождаются до CoUninitialize.

## Не выполнено и ограничения

- Настоящий Silero/Vosk на пользовательской речи: локальные модели не
  предоставлены и не скачивались. Адаптеры проверены автономно с mocks.
- Реальные Ollama/Gemini запросы: сервер/модель и ключ не предоставлены.
- Реальный Edge-TTS: онлайн-запросы не выполнялись.
- Полный разговор и его метрика конец речи → голос: **не измерены**.
- Реальное эхо динамиков не оценивалось. Нет AEC; наушники рекомендованы.
  Временное подавление результатов не разделяет голоса пользователя и динамиков.
- Слышимая плавность требует проверки с подготовленными моделями и LLM:
  аппаратный тест воспроизведения был с нулевой громкостью.

GUI и аппаратные проверки выполнялись отдельно от автоматических тестов.
В песочнице Codex asyncio не мог корректно создать локальный loop, а PyPI
был недоступен по DNS; установка в .venv и проверки выполнены через разрешённый
запуск вне песочницы. Обычный запуск приложения не требует прав администратора.
