# Этап 3: ключ ElevenLabs и конфигурация провайдеров

Дата проверки: 21 октября 2026. Выполнен только этап 3.
Архитектура, прежние вкладки/оформление интерфейса и исправления этапов 1–2
сохранены. Этап 4 не выполнялся.

## Изменения

**Хранилище.** Gemini и ElevenLabs используют общий механизм CredWrite,
CredRead и CredDelete в `alice_voice/secrets.py`. Имена записей:
`AliceVoice/GeminiAPI` и `AliceVoice/ElevenLabsAPI`. Новая запись проверяется
обратным чтением; удаление также проверяется, повторное удаление допустимо.
Нативные сообщения и значения ключей не включаются в ошибки приложения.
Отсутствующая запись отличается от ошибки доступа к хранилищу.

**Настройки и миграция.** Ключа ElevenLabs больше нет среди полей Settings,
поэтому его нет в repr, asdict/to_dict, снимках SettingsStore и новых JSON.
Старое поле понимает только загрузчик миграции:

1. Проверяет весь JSON и остальные настройки.
2. Записывает непустой ключ в Credential Manager и сверяет прочитанное значение.
3. Подготавливает временный JSON без секретов, выполняет flush/fsync и
   атомарно заменяет исходный файл.

При ошибке записи/чтения credential либо очистки JSON исходный файл не
перезаписывается. Запуск показывает понятную ошибку; `--smoke` вместо
модального окна выводит безопасное сообщение и возвращает код 2.
Если credential уже записан, но JSON заменить не удалось, обе копии
сохраняются до повторного запуска. Пустое старое поле удаляется без
обращений к Credential Manager и без удаления уже существующего credential.

Обычный Settings.save не может затереть неперенесённый непустой ключ.
Перед заменой файла его содержимое сверяется с прочитанным исходником.
Это обнаруживает изменения во время переноса, но не является атомарным
compare-and-swap: гонка с внешним процессом между проверкой и os.replace
полностью не исключена. Параллельное редактирование файла несколькими
процессами не поддерживается.

Новые резервные копии исходного JSON не создаются. Временный файл содержит
только очищенные настройки. Старые сторонние резервные копии не изменялись.

**Интерфейс.** В прежних вкладках Gemini и ElevenLabs остаются парольные поля;
сохранённые ключи в них не загружаются. Пустое поле означает «не менять».
Новый текст заменяет ключ; флажок «Удалить сохранённый ключ» удаляет запись
при сохранении. Одновременная замена и удаление отклоняются. При ошибке
введённый текст остаётся доступен для повторной попытки; при закрытии диалога
парольные поля очищаются. JSON не получает даже временного введённого ключа.

Попытка изменить ключ прекращает текущий ответ и перезапускает службы
существующим механизмом reconfigure, даже если остальные настройки не
изменились. Это исключает использование старого состояния провайдера,
в том числе когда запись могла пройти, а проверочное чтение завершилось
ошибкой. Запись в Credential Manager при такой ошибке уже могла измениться;
приложение не утверждает, что хранилище осталось прежним. Действия с двумя
ключами не являются общей транзакцией: успешное первое действие сохраняется,
даже если второе не удалось.

**ElevenLabs.** Перед запросом к LLM runtime проверяет ключ и Voice ID
выбранного ElevenLabs. При отсутствии ключа: «Ключ ElevenLabs отсутствует.
Добавьте ключ в настройках голоса». Недоступность Credential Manager
сообщается отдельно. Каждый синтез получает текущий ключ из хранилища;
в Settings и постоянном кеше провайдера ключа нет. Другой синтезатор не
выбирается автоматически.

**Ollama.** Доступность выбранной модели проверяется ответом `/api/chat`
при каждом запросе. Отдельных сетевых запросов при старте GUI или сохранении
настроек не добавлено. HTTP 404 предлагает выбрать установленную модель
в настройках и посмотреть список через `ollama list`. Ошибка соединения,
таймаут и HTTP 502/503/504 имеют отдельные сообщения о сервере. Тело ответа,
URL и нативный текст ошибки в сообщение не подставляются. Имя модели
отправляется как выбрано пользователем; автоматического fallback нет.
Семантика 404 и серверных ошибок сверена с
[официальным описанием ошибок Ollama](https://docs.ollama.com/api/errors).

## Автоматические тесты: моки

Итоговый полный запуск: **201 тест, OK, 27,103 с, exit 0**.
GUI `--smoke`: **exit 0**. Тесты этапов 1–2 входят в этот запуск.

Добавлены 24 метода: 20 в `tests/test_secure_credentials.py`, 3 в
`tests/test_credential_ui.py`, 1 в `tests/test_reconfigure.py`.
Существующие тесты ElevenLabs переведены на подменяемый загрузчик ключа.

Проверены:

- последовательность записи credential → проверочного чтения → очистки JSON;
- ошибка записи, ошибка и несовпадение обратного чтения, ошибка замены файла;
- сохранение исходного ключа, отсутствие новых резервных копий;
- пустое старое поле, недопустимые настройки, попытка обычной записи поверх
  неперенесённого ключа и изменение файла во время миграции;
- независимые записи Gemini/ElevenLabs, замена, удаление, повторное удаление
  и безопасные сообщения об ошибках хранилища;
- отсутствие ключа до любых LLM/TTS HTTP-запросов, повторное чтение после
  замены, защита от управляющих символов в заголовке;
- запрос именно выбранной модели Ollama, HTTP 404, ошибка подключения,
  таймаут и HTTP 503, отсутствие fallback и содержимого ответа в ошибках;
- настоящие Qt-виджеты с поддельными credential-действиями: пустое поле,
  замена/удаление, конфликт действий, сохранение ввода для повторной попытки,
  сообщение об ошибке, очистка поля при закрытии и обновление runtime.

Все ключи в unittest — фиктивные. Credential Manager и HTTP подменены;
настоящие пользовательские ключи не читаются. Сценарии ошибок и гонок
проверены циклом failing → passing. Полный набор запускался вне песочницы
Windows из-за ограничений asyncio/Qt. В первом полном запуске были исправлены
два выявленных сбоя: ранняя отмена Vision без инициализированного synth и
статический guard вызовов сохранения; атомарная запись вынесена в приватный
помощник без изменения правила о RAM-only аудио.

Итоговый лог: `.build-tmp/stage3-tests.log`.
Лог smoke: `.build-tmp/stage3-smoke.log` (пуст при успехе).
Независимое ревью не выявило оставшихся важных замечаний.

## Реальный Windows Credential Manager

`scripts/qa_secure_credentials.py --live-credentials` выполнен с настоящим
win32cred, **exit 0**. Использована уникальная временная запись QA с
одноразовыми тестовыми значениями, непригодными для API. Производственные
записи Gemini и ElevenLabs этой проверкой не читались и не изменялись.

| Проверка | Результат |
|---|---|
| Запись и чтение | PASS |
| Замена и чтение нового значения | PASS |
| Удаление и проверка отсутствия | PASS |
| Повторное удаление | PASS |
| Миграция непустого тестового JSON | PASS |
| Отсутствие ключа в новом JSON | PASS |
| Отсутствие созданной резервной копии | PASS |

Артефакт содержит только булевы статусы:
`stage3-native-credential-results.json`. Ни значения, ни имя временной записи
в отчёт не выводятся. Проверка подтверждает работу ОС-хранилища, а не
валидность какого-либо реального API-ключа.

## Ограничения и воспроизведение

- Реальные сетевые запросы к ElevenLabs, Gemini и Ollama на этом этапе
  не выполнялись. Доступность действующих ключей/аккаунтов и установленной
  модели Ollama проверяется при реальном запросе; тесты ошибок HTTP — с моками.
- Сбой хранилища после успешной записи может оставить новую запись в нём;
  исходный JSON при неподтверждённой миграции остаётся на месте.
- Старые резервные копии, созданные до миграции другими средствами, этим
  изменением не очищаются. Новые копии Settings не содержат ключей.
- Этап 4, прогрев, endpoint и оптимизация PCM не выполнялись; новые измерения
  задержки ответа не проводились.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m alice_voice --smoke
.\.venv\Scripts\python.exe scripts/qa_secure_credentials.py --live-credentials
```

Нативный скрипт создаёт только временную QA-запись и удаляет её в finally;
временный тестовый JSON также удаляется. В логи и отчёты попадают статусы,
а не ключи. На первом чтении старого рабочего JSON миграция выполняется
автоматически приложением.
