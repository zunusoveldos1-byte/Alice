# Alice streaming and Windows actions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Доработать существующий Alice Voice: обращение «Элис», потоковая озвучка, браузер/Gmail и только черновики Telegram.

**Architecture:** Сохранить capture thread, asyncio dialog thread, synthesis executor и Qt main thread. Ввести ограниченный конвейер текстовых фрагментов и PCM с подтверждением потребления; команды выполнять детерминированно до LLM. Telegram вынести в проверяемый адаптер, отказывающий при неподтверждённой идентичности чата.

**Tech Stack:** Python 3.11+, unittest, PyQt6/QAudioSink, Silero ONNX, Vosk, httpx/Ollama, SAPI/Edge, Windows UI Automation. Способ доступа к UIA выбрать после проверки доступности дерева установленного Telegram; новую зависимость добавлять только если она необходима.

**Spec:** [2026-10-15-alice-streaming-actions-design.md](../specs/2026-10-15-alice-streaming-actions-design.md), утверждена пользователем 15 октября 2026 ответом «Давай».

## Global Constraints

- Изменяется только существующий Alice Voice.
- Никаких отправок, звонков и чтения почты.
- 350 мс тишины округляются до 352 мс при кадрах 32 мс.
- Окно выдачи PCM: два ожидающих фрагмента плюс текущий; текстовая очередь — два фрагмента.
- Аудио и ответы хранятся в RAM; GUI не выполняет join/result.
- Цель — около секунды при прогретых моделях; 50 мс TTS не является гарантией.
- Отдельное «Элис» ожидает один запрос 5 секунд; отмена и отключение сбрасывают ожидание.
- Неизвестные алиасы и неподтверждённая UIA-идентичность адресата не допускают набор.
- Git отсутствует; не создавать репозиторий и не выполнять фиктивные commits. После каждого задания фиксировать проверку в журнале этого плана.

## Review Focus

1. Смена окна пользователем во время Telegram-действия: не вводить в другое приложение (задание 2).
2. Одинаковые имена, группы и неоднозначная граница адресат/сообщение: только однозначный настроенный алиас (задание 2).
3. Отмена при заполненной очереди: producer и consumer завершаются без зависания (задание 5).
4. Пауза в момент исчерпания очереди: следующий фрагмент не звучит до resume (задания 4–5).
5. Закрытие окна после начала речи и до конца HTTP: все workers закрываются, поздний PCM не воспроизводится (задание 5).

- `playback.py`: сохранить однобуферный PCMPlayback; очередь принадлежит controller.
- `config.py`, `recognition.py`, `settings.json`, `ui.py`: настройки и состояние.
- Новые `tests/test_activation.py`, `test_actions.py`, `test_telegram.py`, `test_streaming.py`; расширить существующие integration/services/core tests.
- Новый `scripts/latency_check.py`; обновить README и docs/validation.md после фактических проверок.

## Задание 4: очередь PCM в контроллере

**Files:** controller.py, workers.py (контракты signals), playback.py при выявленной необходимости; tests/test_streaming.py, test_integration.py.

**Interfaces:** сохранить `pcm(token, pcm, ready)`; добавить `pcm_credit(token: int) -> None` в runtime для возврата места. У каждого token последовательный внутренний индекс фрагмента. Controller хранит deque ожидающих PCM и отдельные `playing`, `producer_done`, `response_paused`, `first_started`. Начальная выдача runtime ограничена тремя кредитами: текущий и два ожидающих. Кредит возвращается после завершения конкретного буфера, не при помещении в очередь.

- [ ] Написать failing controller tests с fake playback/runtime: второй PCM не вызывает stop/play до окончания первого; FIFO; dialog_done до/после последнего PCM даёт ровно одно finish; пустая очередь без dialog_done оставляет token активным; отмена очищает очередь; поздние PCM/done/credit игнорируются; пауза в промежутке действует на следующий PCM.
- [ ] Запустить тесты до RED.
- [ ] Подключить dialog_done к controller. На PCM начать первый либо добавить следующий. При buffer finished освободить кредит и продолжить очередь; завершать всю реплику только при producer_done и пустом выходе. Сохранить EchoGuard/busy на промежутках. Метрику speech_end_to_voice писать только при первом ActiveState; pcm_to_playback — для каждого фрагмента. Не позволять поздним stage менять playback на llm.
- [ ] Ограничить сумму байтов очереди и текущего буфера: 32 МиБ (`MAX_PCM_BYTES`). Превышение отменяет реплику с безопасной ошибкой, а не блокирует GUI. При отмене сначала инвалидировать token, затем останавливать выход и освобождать очередь.
