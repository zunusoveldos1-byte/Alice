# Повторное использование VAD/Vosk — 30 октября 2026

Тяжёлые объекты моделей сохраняются между выключениями микрофона: ONNX-сессия
Silero VAD и веса `vosk.Model`. Новый `SileroVAD` создаёт собственные массивы
состояния и контекста. Новый `VoskRecognizer` создаёт отдельный
`KaldiRecognizer`, списки сегментов и статистику распознавания. PCM, текст
пользователя и история аудиопотока в кеш не попадают.

`LocalModelCache` хранит один последний успешно загруженный объект. Блокировка
сериализует конкурирующую загрузку. Ключ включает полный путь, размер и время
изменения файла; для каталога Vosk — также метаданные вложенных файлов.
Смена пути или файлов вызывает перезагрузку. Исчезнувший файл не заменяется
устаревшей копией из RAM. Неудачная загрузка не публикует новый объект и может
быть повторена. При замене модели старый объект может временно жить у уже
запущенного сеанса, пока тот не завершится.

Цена ускорения — удержание последней модели каждого типа в RAM до выхода
из приложения или замены модели. Перезапуск приложения требует холодной
загрузки. Микрофон Lenovo, режим активации, выбор LLM и прогрев TTS не менялись.

## Замеры настоящих моделей

`scripts/qa_capture_model_cache.py` последовательно создаёт четыре capture
worker с настоящими моделями. Вместо аудиоустройства используется заглушка:
она отмечает вызов `open` и сразу останавливает worker. Сеть, микрофон и LLM
не используются; RNNoise отключён в обеих сериях для выделения загрузки моделей.

Две серии в отдельных процессах, без параллельных тестов. В baseline перед
каждым сеансом создаётся пустой кеш, воспроизводя повторную загрузку прежнего
поведения; в cached кеш живёт между сеансами. Замеры включают создание нового
распознавателя Vosk и проверку метаданных файлов.

| Сеанс | До вызова открытия, без кеша | С кешем | Загрузок VAD/Vosk с кешем |
|---|---:|---:|---:|
| Первый | 1550,1 мс | 1147,3 мс | 1 / 1 |
| Второй | 691,2 мс | 77,2 мс | 0 / 0 |
| Третий | 1108,5 мс | 73,2 мс | 0 / 0 |
| Четвёртый | 1583,5 мс | 80,6 мс | 0 / 0 |

Разница первых запусков отражает разброс холодной загрузки; кеш не устраняет
её стоимость. Для повторных запусков диапазон подготовки сократился с
691–1584 мс до 73–81 мс. Это диагностическая выборка, не p95 и не измерение
полной задержки включения физического микрофона. Скорость драйвера, RNNoise,
первое распознанное слово и ответ модели здесь не измерялись.

Данные: [без кеша](capture-model-cache-baseline-results.json),
[с кешем](capture-model-cache-after-results.json).

```powershell
.\.venv\Scripts\python.exe scripts\qa_capture_model_cache.py baseline --output docs\capture-model-cache-baseline-results.json
.\.venv\Scripts\python.exe scripts\qa_capture_model_cache.py cached --output docs\capture-model-cache-after-results.json
```

## Проверки

Полный набор `python -m unittest discover -s tests -v`: **447 тестов, OK,
56,923 с**. Синтаксис изменённых Python-файлов проверен через `compileall`.

Проверены повторное использование моделей при раздельных состояниях,
сброс одного сеанса без изменения другого, новый распознаватель Vosk,
изменение и удаление файлов, изменение вложенных весов Vosk, смена пути,
повтор после ошибки и единственная загрузка при параллельных обращениях.
Тесты на настоящей ONNX-модели проверяют тишину, валидацию кадров и
воспроизводимость результата после сброса.
