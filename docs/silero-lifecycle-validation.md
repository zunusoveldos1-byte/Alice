# Жизненный цикл Silero — 23 октября 2026

Источник текста «Загружаю Silero в память…» — `MainWindow._mode`, стадия
`silero_loading`. Текст использовался только как статус; он не добавлялся в историю
и не передавался на озвучку.

В приложении уже существовал общий `_CACHE`. Обычные повторные реплики и новый
адаптер Silero при тех же настройках переиспользовали модель. Найдена другая причина
реальной повторной загрузки: отмена/таймаут первого запроса проверялись сразу после
загрузчика, до сохранения готовой модели. Результат отбрасывался вместе с запросом,
поэтому следующий запрос загружал модель заново. Отмена при скачивании также
прерывала общую подготовку. Кроме того, попадание в кэш повторяло `silero_ready`,
а интерфейс относил готовность к состоянию загрузки.

Исправление:

- Начатая загрузка принадлежит общему сервису модели, а не первой реплике.
  Отмена речи не отменяет и не обнуляет начатую подготовку модели.
- Под блокировкой выполняется одна инициализация, затем публикуется готовая модель.
  Остальные обращения ожидают её. Отменённый запрос не получает PCM.
- Сервис сохраняется между адаптерами и обработчиками диалога в одном процессе.
  Смена голоса, страницы, открытие настроек и мини-ассистента его не пересоздают.
  Изменение ключа конфигурации CPU допускает новую загрузку; смена голоса — нет.
- Ошибка не публикует модель и освобождает блокировку: следующая попытка разрешена.
- Попадание в готовый кэш не отправляет стадии загрузки/готовности. Реальная
  загрузка по-прежнему показывает статус, который исчезает после готовности.
- Последовательная очередь PCM, отмена текущего запроса и проверка устаревших
  токенов остаются прежними. Остановка речи не выгружает веса.

Новые тесты сначала воспроизвели четыре нарушения: повторный загрузчик после
отмены загрузки, повторное скачивание, повторная инициализация при конкурентном
запросе и повторный статус кэша. После исправления они проходят. Дополнительно
проверены повтор после ошибки и смена голоса без загрузки.

Проверки:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
# Ran 357 tests — OK
.\.venv\Scripts\python.exe scripts/check_silero_lifecycle.py
```

Вторая команда запускает настоящую локальную `v4_ru`, получает четыре PCM-ответа
в RAM, отменяет первый запрос во время инициализации и отдельную речь во время
синтеза, открывает три страницы, настройки и мини-ассистент в offscreen Qt.
Затем создаёт новый executor и адаптер. Аудио не воспроизводится и не сохраняется,
микрофон и LLM не используются.

Результат диагностического сеанса: `silero_model_init_start` — один раз,
`silero_model_init_ready` — один раз, затем семь `silero_model_reuse`.
Первая инициализация заняла около 2,17 с. Итог:

```text
stage=silero_lifecycle_verified initializations=1 completed_pcm=4 cancelled_pcm=1 pages=3 mini=1 settings=1 executors=2
```

Лог последнего запуска: `.build-tmp/silero-lifecycle.log`. Диагностика записывает
только стадии и счётчики; обычное приложение не создаёт этот файл автоматически.
Для загрузки исправления нужно перезапустить ранее запущенный экземпляр Alice.
