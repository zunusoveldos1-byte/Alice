# Режим «Ярмарка» — 23 октября 2026

## Использование

Голосовое переключение: «Протокол Ярмарка» включает ограниченную активацию и RNNoise.
«Ярмарка стоп» выключает протокол без предварительного имени помощника. Можно также
произнести команды с именем: «Алиса, протокол ярмарка». Необязательная проверка владельца применяется к фоновой активации в «Ярмарке»,
собственная озвучка не переключает режим. Используются только финальные точные фразы.
При выключении возвращается прежний обычный режим шумоподавления; если он неизвестен,
шумоподавление выключается. Изменение сохраняется обычным механизмом настроек.

Перезапустите Alice. В «Настройки → Ярмарка» включите режим, выберите микрофон
и шумоподавление. По умолчанию новые возможности выключены, прежний разговорный
режим сохранён. Режим шумоподавления «Ярмарка» также включает ограниченную активацию;
«Обычный» использует один RNNoise без ограничения обычного диалога. Можно включить
ограниченную активацию с выключенным шумоподавлением.

Для демонстрации рекомендуемый вариант — близкий микрофон и удержание кнопки
«Удерживать, чтобы говорить» либо Ctrl+F8. Клавишу можно изменить на F1–F12
с Ctrl/Alt/Shift. Повтор нажатой клавиши не создаёт повторных запросов.
После холодного запуска дождитесь готовности микрофона и состояния «Слушаю вас»
перед началом речи; первая подготовка моделей выполняется в фоне.
При отпускании собирается короткий хвост 96 мс, затем финализируется одна команда.
Сохраняется предварительный буфер из настройки «Преролл» (по умолчанию 320 мс).

Альтернатива: «Алиса, открой блокнот» или отдельное «Алиса», затем команда в течение
пяти секунд. Имя должно быть первым словом и совпадать точно. Одна команда закрывает
окно; продолжение разговора выключено. При необходимости его можно включить:
после ответа открывается ещё одно короткое окно. Это не бесконечный приём.

Проверка владельца использует уже существующую ONNX-модель аудиопризнаков и локальный
профиль из трёх записей. Регистрация, повторная запись и удаление доступны в настройках.
Лучше записывать профиль в тишине. Порог сходства не является процентом уверенности.
Удержание — отдельное явное разрешение на одну команду без проверки личности.
Регистрация профиля не включает проверку автоматически. В обычном общении профиль
не требуется, даже если в старых настройках сохранился включённый флаг владельца.
Модель проверки владельца создаётся лениво только при фоновой проверке в «Ярмарке»;
отсутствие этой модели не препятствует ручному удержанию.
Выключение и перезагрузка сохраняют два отдельных подтверждения; в режиме ярмарки
каждое подтверждение тоже активируется именем или отдельным удержанием.

## Обработка и ограничения

PortAudio сохраняет прежний формат PCM16 mono, 16 кГц / 512 отсчётов. В worker,
вне callback и GUI: потоковый soxr 16→48 кГц, RNNoise кадрами 480 отсчётов,
soxr 48→16 кГц и переупаковка в кадры 512 для существующих Silero VAD и Vosk.
RNNoise DLL загружается один раз в процессе; одно состояние создаётся на поток
захвата и сохраняется между фразами. Состояния ресемплеров непрерывны.
Несколько шумодавов последовательно не включаются, автоматического усиления нет.
Очередь захвата и внутренние буферы ограничены; потерянная фраза отбрасывается.

VAD сохраняет настройку преролла, минимальной речи и задержки окончания.
Минимальная речь по умолчанию — 96 мс вместо 320 мс: законченные короткие слова
допускаются, одиночный шумовой кадр отбрасывается. При явном удержании нет
дополнительного порога длительности или проверки владельца после распознавания.
Для ярмарки
отдельно доступен порог VAD 0,65 и минимальное качество STT 0,65. Это начальные
настройки, **не откалиброванные на голосах участников**. Промежуточные результаты
не активируют и не выполняют команды. Неразборчивая активированная фраза показывает
«Не расслышала. Повторите» без озвучивания. Детектора перекрывающихся голосов и
определения ближайшего человека здесь нет. RNNoise не выделяет владельца из разговора других людей.

Для колонок применяется явно обозначенный полудуплекс: при воспроизведении и его
хвосте команды не принимаются. Удержание сначала останавливает озвучку, затем ждёт
окончания защитного хвоста перед «Слушаю вас». Преролл не включает этот хвост.
Это **не WebRTC AEC**. Параметр «Наушники» следует включать только при их использовании.

## Проверка микрофона

Кнопка запускает четыре секунды записи только по явному нажатию. Показываются
входной уровень, наличие речи и перегрузка; можно прослушать исходное и обработанное
PCM. Запись хранится в RAM и удаляется при закрытии. Команды во время теста и
прослушивания блокируются. Если поток уже открыт с теми же параметрами, тест
использует его, не открывая второе устройство. Сначала сохраните изменённый микрофон
или режим обработки. При закрытом микрофоне создаётся временный тестовый поток.

## Проверено

- Автотесты: точное имя, одноразовое окно и таймаут, чужие неактивированные фразы,
  отключённое имя, низкое качество STT, глобальная клавиша без повторов, сохранение
  параметров, мини-ассистент, закрытие теста без открытия микрофона.
- Два удержания подряд на непрерывном синтетическом VAD-сигнале, завершение после
  отпускания, ограниченный преролл, сохранение новой команды при сбросе старого потока.
- Остановка ответа с прероллом: явное удержание не отбрасывается из-за интервала
  предыдущего ответа. Проверки эпохи/ревизии/устаревших токенов сохранены.
- Защита от собственной озвучки проверена на временных интервалах без настоящих
  колонок. Подтверждения питания проходят существующие тесты с подменённым исполнением.
- Настоящая RNNoise DLL: размер 480, повторное использование состояния, сброс
  ресемплеров, фиксированные выходные кадры, ограниченные буферы.
- Неразборчивая речь показывает короткое уведомление без запроса LLM, инструментов
  и озвучивания. Повторные уведомления ограничены по частоте.
- Короткие «Привет», «Да», «Нет», «Спасибо» проходят конвейер захвата с подменёнными
  VAD/STT в обычном режиме и при удержании в «Ярмарке», без модели владельца.
  Тишина и одиночный шумовой кадр по-прежнему отбрасываются. Это проверка логики,
  не испытание настоящего голоса с микрофона.
- GUI smoke и `pip check` прошли.

## Сравнение синтетического аудио

`scripts/check_fair_audio.py` не включает микрофон, не воспроизводит звук и не
исполняет команды. Он создаёт речь Silero и шум, обрабатывает RNNoise, распознаёт
обе версии настоящим Vosk. Результаты: `.build-tmp/fair-audio-validation.json`.

| Синтетический случай | Исходный | Обработанный |
|---|---|---|
| «Алиса открой блокнот» в тишине | Все слова совпали | Все слова совпали |
| Та же фраза с белым шумом | Все слова совпали | Все слова совпали |
| Только белый шум | Пустой текст, без активации | Пустой текст, без активации |
| Два синтетических голоса одновременно | WER 0,33 | WER 0,67: хуже |

На этих четырёх коротких примерах измеренное время обработки 3,46 с аудио составило
204–311 мс. Остаток недовыданного аудио был около 38,5 мс,
включая неполный последний кадр. Это **не измерение всей задержки «голос → ответ»**.
Первое слово в двух одиночных фразах сохранилось. Одного набора недостаточно для
оценки частоты ложных активаций или пропуска команд на настоящей ярмарке.

Реальных записей пользователя, разговоров других людей и озвучки через колонки
нет. Испытания в толпе, калибровка порогов владельца и физическая проверка начала
слов/горячей клавиши **не проводились**. Приложение не заявляет их пройденными.

## Повторная установка и проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-fair.txt
.\.venv\Scripts\python.exe scripts/prepare_rnnoise.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe scripts/check_fair_audio.py
.\.venv\Scripts\python.exe -m alice_voice --smoke
```

В текущей среде зависимости и DLL уже подготовлены. Скрипт подготовки извлекает
только native DLL из закреплённого Windows x64 wheel и проверяет SHA-256; тяжёлые
CLI/AV-зависимости оболочки не устанавливаются. Источники:
[RNNoise](https://github.com/xiph/rnnoise),
[Python-оболочка и C API](https://github.com/pengzhendong/pyrnnoise).
