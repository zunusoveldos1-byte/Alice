# Alice Voice: QA и оценка зрелости архитектуры

Дата: 21 октября 2026. Проверена текущая версия файлов в рабочем каталоге.
Код приложения и пользовательские настройки в ходе аудита не изменялись.

## Итог: 60/100 — развитый прототип, до production остаются блокирующие пробелы

Оценка экспертная: пять направлений с одинаковым весом 20 баллов.
Она не является процентом успешно пройденных автоматических тестов.

| Направление | Баллы | Основание |
|---|---:|---|
| Disfluency / Intent Recovery | 10/20 | Детерминированный быстрый фильтр; два смысловых дефекта и один частичный результат на заданных сценариях |
| Latency | 9/20 | Есть метрики этапов и потоковый LLM; реальные диагностические E2E 2,14–2,61 с, холодный аудиовыход около 2 с |
| Cancellation / Barge-in | 11/20 | Ручной stop, отмена задач и освобождение очередей работают; голосовое «Стоп» и VAD barge-in отсутствуют |
| Screen Vision | 18/20 | Выбор источника, проверяемое превью, координаты области, ограниченные RAM-буферы; запрос с реальным изображением в Gemini не выполнялся |
| Безопасность / конфигурация | 12/20 | Gemini в Credential Manager; ElevenLabs предусмотрен в открытом JSON и в текущем конфиге не настроен |

Положительные архитектурные свойства: короткий PortAudio callback, отдельные
потоки захвата и диалога, asyncio TaskGroup, bounded queues и credits,
идентификаторы поколений/дедупликация, безопасные сообщения об ошибках,
сохранение настроек вне GUI и ограниченная история. Это последовательный
VAD → STT → LLM → TTS pipeline с потоковым текстом и синтезом предложений;
полного duplex speech-to-speech пока нет.

## Методика и ограничения

- Полный unittest: **144 теста, OK, 25,718 с**. GUI `--smoke`: exit 0.
- Сценарии фильтра: по 1000 измерений после 100 прогревочных вызовов.
- Реальный Gemini: 3 коротких запроса; выбранный Ollama: один запрос, HTTP 404.
- STT: настоящие локальные Silero ONNX и Vosk на синтетической русской речи
  «Сколько будет два плюс два?», сформированной SAPI в RAM, N=5.
- Диагностический E2E: N=3, те же PCM-кадры подаются в CaptureWorker с шагом
  32 мс, затем настоящий controller/runtime → Gemini → SAPI → QAudioSink.
  Микрофон заменён повторяемым источником. Громкость выхода 0.
- В E2E SAPI выбран только для теста: текущий `synthesizer=elevenlabs`,
  но ключ пустой. Работу штатной связки Gemini + ElevenLabs не подтверждаем.
- Конечная точка TTFA — QAudioSink ActiveState, не акустический сигнал с
  динамика. Акустическая задержка, качество распознавания живого человека,
  AEC и удалённое прекращение вычислений/биллинга не измерялись.
- Отмена HTTP проверена через реальные клиенты приложения с MockTransport,
  N=20 для LLM и N=20 для TTS. Эти числа не являются сетевым RTT.
- Vision: настоящий захват главного монитора, N=8; изображения не сохранялись
  и не передавались в сеть. Размер HTTP-тела измерен на MockTransport.
- Малые N у сетевых/нативных тестов не позволяют заявлять production p95/SLO.

## 1. Заданные сценарии фильтра — фактические clean_query

| Сценарий | Фактический результат | Вердикт |
|---|---|---|
| Поставь таймер на семь... ой нет, точнее на восемь минут | `на восемь минут` | FAIL: утрачено действие |
| Открой браузер и найди погоду... хотя нет, забудь, открой блокнот | `открой блокнот` | PASS |
| Эээ, ну короче, типа покажи мне, как написать класс на C#, ну ты понял | `покажи мне, как написать класс на C# ты понял` | PARTIAL: паразиты удалены, хвост «ты понял» остался |
| Что такое типа данных string? | `Что такое данных string?` | FAIL: удалено смысловое «типа» |

Причина первого дефекта: два соседних маркера «ой нет» и «точнее» образуют
пустое промежуточное исправление. `_repair(previous, '')` сбрасывает previous,
и следующему исправлению нечего восстанавливать. Причина четвёртого:
защита «типа» смотрит на ограниченный список предыдущих слов, но не видит
последующее «данных». Маркер «хотя нет» отдельно тоже не поддержан;
во втором сценарии помогает последующий «забудь».

Это не нейросетевая семантическая модель. Система также не открывает
реальные приложения: очищенный императив лишь поступает в LLM.

## 2. Задержки

| Этап | Результат |
|---|---|
| Ожидание endpoint | Номинально ceil(650 / 32) × 32 = 672 мс; в replay 670–678 мс |
| Последний речевой VAD-кадр → текст STT | 693–697 мс в replay, включая ожидание тишины |
| Vosk FinalResult/reset | N=5: median 14,73 мс; p95 28,71 мс. В replay 16,32–20,88 мс |
| Disfluency на четырёх сложных строках | median 0,022–0,054 мс; p95 максимум 0,067 мс |
| Gemini, отдельный TTFT | 2203,16 / 465,48 / 1313,16 мс; первый запрос включает model check и холодный HTTP |
| Gemini TTFT в replay | 1083,45–1484,74 мс |
| Первый чанк LLM → QAudioSink ActiveState | 354,05 / 391,99 / 596,81 мс в replay |
| SAPI-подготовка первого предложения в replay | 83,06–121,62 мс |
| Готовый PCM → ActiveState в replay | 194,96–346,49 мс |
| Отдельный нативный аудиотест | Холодный запуск 2074,55 мс; следующие четыре 66,58–117,56 мс |
| Конец речи → первый ActiveState | **2577,01 / 2612,10 / 2136,11 мс**, median **2577,01 мс** |

**Цель <1,5 с не достигнута: 0 из 3 диагностических запусков.** В текущей
конфигурации ElevenLabs ключ отсутствует, поэтому нормальный голосовой ответ
блокируется до запроса TTS. Альтернативная выбранная модель Ollama `qwen3:4b`
вернула HTTP 404; причина отсутствия доступной модели этим тестом не уточнялась.

Не следует складывать несвязанные median разных тестов и называть сумму E2E.
Суммарные числа выше взяты из production-метрики `speech_end_to_voice`
в одном и том же проходе. Метрика `tts` сама по себе не включает ожидание
первого предложения, передачу PCM в GUI и запуск аудиоустройства.

Узкие места: фиксированные ~0,67 с тишины; TTFT Gemini; ожидание границы
предложения перед TTS; полная подготовка PCM предложения перед playback;
повторное создание QAudioSink для каждого PCM. Начальные загрузки моделей
и аудиовыхода дополнительно ухудшают первый запуск.

## 3. Отмена и barge-in

- Настоящий `cancel_response()` + QAudioSink, N=5: median **0,130 мс**,
  p95 **0,919 мс**, максимум **1,115 мс** до возврата с `StoppedState`.
  PCM-очередь пуста, QBuffer освобождён, активный токен сброшен во всех пробах.
- LLM: отмена → завершение задачи median **0,515 мс**, p95 **0,792 мс**.
- ElevenLabs TTS на MockTransport: median **0,490 мс**, p95 **0,535 мс**.
- Во всех 40 HTTP-пробах ответы закрылись, session/history очищены.
  Локальная `asyncio.Queue(maxsize=2)` в TTS-тесте была заполнена двумя
  предложениями и освобождалась после отмены; явного drain/clear в продукте
  нет. Проверена сборка очереди через weakref после завершения задач.
- Голосовое **«Стоп» не распознаётся как управляющая команда**.
- Обычный новый речевой запрос при воспроизведении не прерывает ответ.
  Нет отдельного сигнала от VAD speech-start к немедленной отмене playback.
- «Отключайся» прерывает ответ при `headphones=True`; без наушников результат
  подавляется EchoGuard во время воспроизведения. Это финальная STT-команда,
  а не мгновенное прерывание на первом VAD-кадре.

На Windows ручной stop в этом замере быстрый. Для переносимого hard-stop
целесообразно рассмотреть `QAudioSink.reset()`: Qt документирует немедленное
отбрасывание буферов; `stop()` на Linux/Darwin может дренировать буфер.
Источник: https://doc.qt.io/qt-6/qaudiosink.html#reset

## 4. Screen Vision

Голосовой триггер открывает превью; HTTP-запрос начинается после подтверждения.
Автоматические проверки подтвердили дедупликацию, выбор монитора/окна/области,
пересчёт координат с отрицательным origin, отмену и передачу именно показанного
JPEG без повторного захвата. JPEG не сохраняется в истории.

- Полный capture + resize + encode, N=8: median **182,76 мс**, mean 327,23 мс;
  первый/самый медленный вызов 1138,73 мс.
- Resize: median **76,89 мс**. JPEG encode: median **13,49 мс**.
- Изображение **1280×720**, **93 500 байт** JPEG в данном содержимом экрана.
- Base64: **124 668 байт**; полный JSON HTTP body: **125 578 байт**
  (текст, system prompt и generationConfig включены, HTTP-заголовки не включены).
- Размер зависит от содержимого; Base64 добавляет примерно треть к JPEG.
- Задержка 150 мс перед обычным UI-захватом, 3 секунды для активного окна
  и время ручной проверки превью в CPU-бенчмарк не включены.
- Непрерывной трансляции кадров нет: реализованы явные одиночные снимки.

## 5. Ключи и конфигурация

Gemini: `secrets.py` использует CredWrite/CredRead и target
`AliceVoice/GeminiAPI`; credential доступен. Значение ключа не выводилось.
В текущем JSON поля ключа Gemini нет.

ElevenLabs: `Settings.elevenlabs_api_key` сериализуется через asdict в
settings.json и читается провайдером непосредственно из Settings. Credential
Manager для ElevenLabs не реализован. В текущем JSON поле есть, но оно пустое:
обнаружена архитектурная уязвимость хранения, а не утечка действующего ключа.
Password echo mode и repr=False не шифруют JSON.

Исправление: перенести ElevenLabs в отдельный generic credential,
мигрировать старые конфиги и исключить ключ из Settings.to_dict/save.
Рекомендация Microsoft: https://learn.microsoft.com/en-us/windows/win32/secbp/handling-passwords

## Приоритетные дальнейшие действия

Сначала закрыть функциональные блокеры: ключ/голос ElevenLabs и доступность
Ollama; регрессии фильтра; голосовую команду «Стоп» и политику barge-in;
хранение ElevenLabs в Credential Manager.

Три основных направления повышения производительности:

1. **Адаптивный endpoint.** Экспериментально подобрать 250–350 мс для коротких
   команд вместо фиксированных 650 мс, измеряя ложные окончания на русской
   речи. Потенциально высвобождает несколько сотен мс; результат ещё не проверен.
2. **Снизить и стабилизировать TTFT.** Прогрев соединения/модели и выбор
   доступной малолатентной модели по реальным median/p95. Переиспользование
   клиента в DialogRuntime уже есть; не нужно создавать клиент на каждую реплику.
3. **Ускорить первый звук.** Прогреть и переиспользовать аудиовыход, перейти
   к инкрементальной подаче PCM и более раннему TTS коротких фрагментов.
   Проверить настоящий ElevenLabs streaming TTFA; сейчас тело аудио предложения
   собирается целиком, несмотря на использование HTTP stream.

## Воспроизведение

Из корня проекта, в среде с доступом к Windows desktop/audio и локальным
сокетам asyncio:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m alice_voice --smoke
.\.venv\Scripts\python.exe scripts/qa_architecture_audit.py --live
.\.venv\Scripts\python.exe scripts/qa_native_latency.py --live-replay
```

`--live` и `--live-replay` выполняют короткие реальные LLM-запросы и могут
расходовать квоту. В отсутствие флагов HTTP cancellation использует mocks;
локальные проверки всё равно читают экран в RAM и используют аудиоустройство
с громкостью 0. Ни скрипты, ни отчёты не содержат ключей, JPEG или PCM.

Сырые числовые результаты: `qa-architecture-results.json`, `qa-native-results.json`.
