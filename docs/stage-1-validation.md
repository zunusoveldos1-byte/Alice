# Этап 1: конфигурация и безопасная инициализация

Дата: 20 октября 2026 года. Изменения ограничены этапом 1.

## Изменения

- Строгая проверка типов всех полей Settings до проверки диапазонов.
  bool не принимается вместо int/float; целые значения разрешены для
  вещественных параметров. Некорректные корни JSON, NaN, бесконечности,
  отрицательные индексы микрофона и неправильные порты URL отклоняются.
- Атомарное сохранение JSON: временный файл в том же каталоге, flush,
  fsync, закрытие дескриптора, os.replace. Ошибка до замены сохраняет
  исходный файл; временный файл удаляется при обработанных исключениях.
- Создание event loop, executor, provider и synthesizer защищено одним
  жизненным циклом с независимым освобождением созданных ресурсов.
- Публикация loop и cross-thread scheduling синхронизированы; закрытый
  loop не выпускает RuntimeError в GUI. Ошибка создания task закрывает
  неиспользованную coroutine и сообщает об отказе обработки.
- Controller обрабатывает ошибки конструкторов/Thread.start, останавливает
  захват при отказе службы и игнорирует поздний loading остановленного worker.
- Логи инициализации содержат этап, длительность или класс ошибки,
  без значений настроек и текста исключений внешних компонентов.

## Проверки

1. Новые регрессионные тесты сначала воспроизвели дефекты исходной реализации.
2. Полный `python -B -m unittest discover -s tests -v`: 53 теста, OK;
   20 тестов добавлены в test_stability.py. Проверены ошибки fsync/replace,
   неверные типы каждого поля, отказы loop/executor/provider/task,
   отмена при очистке, закрытый loop и shutdown во время инициализации.
3. `python -B -m alice_voice --smoke`: код 0, микрофон не открывался.
4. `python -m pip check`: No broken requirements found.
5. Отдельное read-only ревью этапа 1: существенных замечаний нет.

Полный набор запускался вне песочницы из-за ограничений Windows asyncio
в песочнице. Тесты не используют настоящий микрофон, ключи или сеть.
Модели и пользовательский settings.json не изменялись.

## Границы этапа

Потоковая озвучка, очереди этапа 2, изменение истории, новый интерфейс и
инструменты не добавлялись. Устранены обработанные ошибки инициализации и
гонки закрытия; зависший нативный драйвер/COM-вызов по-прежнему нельзя
гарантированно прервать без изоляции в отдельный процесс. Ожидание executor
выполняется в фоновом потоке, а не в GUI.
