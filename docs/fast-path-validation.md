# Fast-Path коротких ответов — 30 октября 2026

В обработчике `DialogRuntime._process` добавлена быстрая ветка до запуска LLM.
Точные реплики из `alice_voice/fast_path.py` получают готовый текст и проходят
через существующую очередь предложений, выбранный TTS и очередь PCM. Запрос
генерации LLM, разбор намерения и получение контекста окна для них пропускаются.
Файлы записи и кеш синтезированного аудио не создаются.

## Фразы

| Реплика | Ответ |
|---|---|
| привет | Привет, я слушаю. |
| здравствуй | Здравствуй, я слушаю. |
| здравствуйте | Здравствуйте, я вас слушаю. |
| доброе утро | Доброе утро, я слушаю. |
| добрый день | Добрый день, я слушаю. |
| добрый вечер | Добрый вечер, я слушаю. |
| как дела | Всё хорошо, я готова помочь. |
| спасибо / большое спасибо / благодарю | Пожалуйста, обращайся. |

Регистр, лишние пробелы и завершающие `. ! ? …` не влияют на совпадение.
Совпадение полное: «привет, открой блокнот», «как дела с документом»,
«не говори привет», цитаты, «да», «нет», «стоп» и «отмена» не перехватываются.
При ожидании подтверждения питания, выбора варианта или подтверждения имени
приоритет остаётся у существующего обработчика. Запросы с изображением или
захватом экрана не используют Fast-Path.

Ответ заносится в историю после завершения воспроизведения. Отмена во время
синтеза не сохраняет незавершённый ответ. Ограничения PCM, кредиты, пауза,
выбранный голос и проверка конфигурации TTS сохранены. Fast-Path находится
после существующих правил допуска микрофонной реплики и не отключает их.

Для быстрой ветки записываются метрики `fast_path_ready` и
`fast_path_to_first_pcm`; стадия LLM для такого ответа не отправляется.
Существующий независимый фоновый прогрев провайдера при запуске runtime
остаётся: Fast-Path исключает генерацию конкретного ответа, а не меняет
жизненный цикл сетевых служб.

## Настоящий Silero

`scripts/qa_fast_path.py` использовал локальный v4_ru, выбранный голос baya
и настоящую очередь runtime. Исходящие подключения запрещены, LLM заменён
объектом, для которого проверено отсутствие вызова `stream`. Чтение окна также
запрещено проверкой. PCM подтверждается диагностическим callback без открытия
аудиоустройства, воспроизведения и записи файлов звука.

| Реплика | Начало обработчика → первый готовый PCM | Вызовов генерации LLM |
|---|---:|---:|
| привет | 72,7 мс | 0 |
| спасибо | 92,9 мс | 0 |
| как дела | 117,5 мс | 0 |

В каждом случае создан один пакет PCM; запросов контекста окна — 0.
Предварительный прогрев в отдельном свежем процессе занял 17 115,1 мс.
Fast-Path убирает ожидание LLM, но не стоимость холодного запуска TTS.
При обращении сразу после включения голос ещё может готовиться.

Это по одному наблюдению на фразу после прогрева, не p95 и не измерение
акустического первого звука. STT, ожидание тишины, Qt-аудиовыход и драйвер
в эти числа не входят. [Данные](fast-path-results.json).

```powershell
.\.venv\Scripts\python.exe scripts\qa_fast_path.py
```

## Проверки

Полный набор `python -m unittest discover -s tests -v`: **474 теста, OK,
56,953 с**. Синтаксис изменённых Python-файлов проверен через `compileall`.

Новые тесты покрывают список фраз, составные/отрицательные реплики и цитаты,
отсутствие вызова LLM и чтения окна, передачу выбранному синтезатору, запись
истории только после воспроизведения, отмену, ожидающие подтверждения и
выборы, сохранение обычного потокового ответа и запроса с изображением.
В тестах собственно LLM-потока приветствие заменено арифметическим вопросом,
чтобы они продолжали проверять потоковую генерацию, а не быструю ветку.
