# Фоновый прогрев Silero — 29 октября 2026

При запуске DialogRuntime с warmup=True выбранный Silero готовится в speech
executor параллельно с прогревом LLM. Подготовка включает загрузку весов и два
пробных синтеза «Привет. Я работаю локально.». PCM отбрасывается: сигналы
воспроизведения, этапов ответа и записи истории не отправляются.

Два прохода выбраны после проверки настоящей модели: после единственного
пробного синтеза следующий запрос ещё занимал около 4,4 с. Это наблюдение
согласуется с дополнительной оптимизацией графа PyTorch; сам JIT отдельно
не профилировался.

Успешный прогрев кешируется по числу потоков CPU и голосу для загруженной
модели. Перезагрузка модели очищает отметки. Общая блокировка не допускает
одновременного inference и повторного прогрева одного голоса. Ошибка фоновой
подготовки записывается без текста исключения; обычный запрос может повторить
синтез. Отмена ответа не отменяет подготовку службы. При остановке runtime
отменяется и прогрев: уже выполняющийся нативный вызов завершится, его PCM
отбрасывается, следующий проход не запускается.

## Замеры настоящей модели

Два отдельных свежих процесса, последовательно, без параллельного запуска
тестов. Локальные проверенные веса v4_ru, xenia, 24000 Гц, два потока CPU.
Исходящие подключения запрещены, звук не воспроизводится, LLM не вызывается.
Тестовый ответ «Таймер установлен на восемь минут.» отличается от текста
прогрева; длительность полученного PCM — 1887,5 мс.

| Показатель | Без прогрева | После двух проходов |
|---|---:|---:|
| Первый запрос → готовый PCM | 11 281,6 мс | 123,0 мс |
| Второй запрос → готовый PCM | 6259,5 мс | 81,7 мс |
| Третий запрос → готовый PCM | 80,1 мс | 68,5 мс |
| Инициализаций модели | 1 | 1 |

Фоновая подготовка заняла 13 957,0 мс. Повторный вызов подготовки — 0,374 мс.
Прогрев переносит вычисления до пользовательского запроса, а не устраняет
стоимость холодного запуска. При немедленном запросе после включения
ожидание подготовки остаётся. Это диагностическая пара процессов, а не
распределение задержек: p95 и ускорение для всех текстов не заявляются.
Захват речи, LLM, драйвер вывода и акустический первый звук не измерялись.

Данные: [исходный запуск](silero-warmup-baseline-results.json),
[после прогрева](silero-warmup-after-results.json).

Повторение из корня проекта, каждый вызов отдельным процессом:

```powershell
.\.venv\Scripts\python.exe scripts\qa_silero_warmup.py baseline --output docs\silero-warmup-baseline-results.json
.\.venv\Scripts\python.exe scripts\qa_silero_warmup.py warmup --output docs\silero-warmup-after-results.json
```

## Автоматические проверки

Окончательный полный запуск: `python -m unittest discover -s tests -v` —
**439 тестов, OK, 59,409 с**. Проверка синтаксиса изменённых Python-файлов
через `compileall` завершилась успешно.

Тесты адаптера проверяют отсутствие возвращаемого пробного PCM, повторное
использование модели между адаптерами, смену голоса, перезагрузку модели,
повтор после ошибки, отмену между проходами и параллельные обращения.
Тесты runtime проверяют автоматический прогрев без запроса, независимость
от отмены ответа, перекрытие с LLM и отсутствие записей истории и сигналов PCM.

В песочнице asyncio зависал при создании локальной пары сокетов ещё до тела
теста. Проверки запускались вне песочницы с разрешением пользователя.
