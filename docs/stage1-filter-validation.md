# Этап 1: исправление фильтра оговорок

Дата проверки: 21 октября 2026.
Основание: `qa-architecture-audit.md`, раздел 1.

Изменён только существующий детерминированный `DisfluencyFilter`;
архитектура pipeline, интерфейс, настройки и зависимости сохранены.
Этапы 2–4 не выполнялись.

## Поведение

| Исходная фраза | Результат |
|---|---|
| Поставь таймер на семь... ой нет, точнее на восемь минут | Поставь таймер на восемь минут |
| Открой браузер и найди погоду... хотя нет, забудь, открой блокнот | открой блокнот |
| Эээ, ну короче, типа покажи мне, как написать класс на C#, ну ты понял | покажи мне, как написать класс на C# |
| Что такое типа данных string? | Что такое типа данных string? |

- Пустые промежуточные исправления больше не сбрасывают исходное намерение.
  Пустое последнее исправление по-прежнему отменяет запрос, а «забудь»
  сбрасывает его независимо от наличия следующего маркера.
- «типа» защищено при следующем слове «данных», включая разный регистр.
- Конечные «ну ты понял» и «ну вы поняли» удаляются до одиночных паразитов.
  Цитаты, вопросы «ты понял?» и смысловое «объясни что ты понял» сохраняются.
- Добавлены маркеры «хотя нет» и «а хотя нет».

Это по-прежнему набор эвристик, а не универсальный семантический разбор.
Правило хвостов намеренно ограничено указанными фразами в конце реплики.

## Регрессионные проверки

Добавлены 9 тестовых методов с табличными сценариями, в том числе 3 проверки
границы controller → runtime: в LLM попадают полное действие, технический
термин и текст без паразитного хвоста. Также проверены соседние маркеры,
числа, напоминания, замена города, явный сброс, цитаты и идемпотентность.

До исправления новый набор воспроизвёл 20 неуспешных проверок, включая
подслучаи. После исправления:

- Полный unittest: **153 теста, OK, 23,093 с**, exit 0.
- Отдельный файл фильтра: **20 тестов, OK**.
- GUI `--smoke`: **exit 0**; открытие и закрытие без микрофона.

Первый полный запуск в песочнице перестал продвигаться на проверках asyncio
и был остановлен. Успешный полный запуск выполнен вне песочницы Windows,
как и в исходном аудите. Логи находятся в
`.build-tmp/stage1-tests-desktop.log`, `.build-tmp/stage1-filter-green.log`
и `.build-tmp/stage1-smoke.log` (последний пуст при успешном запуске).

Команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_disfluency_filter.py -v
.\.venv\Scripts\python.exe -m alice_voice --smoke
```

## Время работы фильтра

Использован существующий `filter_check()` из `scripts/qa_architecture_audit.py`
без запуска остальных частей аудита: 100 прогревочных и 1000 измеряемых
вызовов на каждый из четырёх сценариев. Все четыре результата — PASS.
Числа округлены; сырые результаты: `stage1-filter-results.json`.

| Сценарий | Медиана, мс | p95, мс |
|---|---:|---:|
| Таймер, «ой нет, точнее» | 0,0293 | 0,0422 |
| Замена команды на блокнот | 0,0259 | 0,0345 |
| C# и паразитный хвост | 0,0214 | 0,0268 |
| «типа данных string» | 0,0105 | 0,0147 |

Это локальный микробенчмарк фильтра, выполненный во время полного тестового
запуска; он не измеряет VAD/STT/LLM/TTS и не доказывает улучшение E2E.
Задержка «конец речи → первый звук» в этом этапе не измерялась;
достижение цели менее 1500 мс не подтверждено.
