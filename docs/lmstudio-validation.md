# Проверка LM Studio — 21 октября 2026

Добавлен адаптер LM Studio за существующим LLMProvider. Ollama/Gemini,
существующий аудиоконвейер, голосовое прерывание и интерфейс сохранены.
Настройки дополнены LM Studio, адресом /v1, ID модели, необязательным токеном
и фоновой проверкой подключения. Рабочий settings.json не изменялся;
ожидание тишины осталось 650 мс. Модель не подменяется автоматически.

## Подтверждено автоматическими проверками

- Полный набор: **254 теста, OK, 25.394 с**.
- Настоящий GUI `python -m alice_voice --smoke`: код выхода 0.
- GUI `--smoke` с LM Studio в отдельном QA-файле настроек: код выхода 0.
  Это проверка открытия окна без микрофона и генерации, не проверка сервера.
- 22 новые регрессии: 16 адаптера, 3 настроек/хранилища, 2 Qt-настроек,
  1 интеграционного конвейера. HTTP/LLM/TTS в этих регрессиях замоканы.
- SSE, ID модели, Bearer, таймаут/отключённый сервер/401/403/404/503,
  раннее закрытие и повторная отмена HTTP, PCM до завершения HTTP,
  очистка сессии и отсутствие коммита прерванной истории.
- Фрагментированные аргументы tool calling, JSON/типы/лишние поля,
  неизвестное имя и незавершённый вызов, tool-ответ и продолжение LLM,
  отмена инструмента и запрет запуска следующего. Даже если обработчик
  перехватил CancelledError, последующие запросы и действия не запускаются.
- Reasoning в отдельных полях, разрезанные и вложенные теги исключены из
  озвучки. Пустой ответ и оборванный поток дают понятную ошибку.
- Qt: токен не попадает в Settings, сохранение/удаление через тот же механизм,
  фактические ID из списка, отбрасывание результата проверки после изменения
  URL/токена/модели, сохранение явно выбранного ID без автоматической замены.

Независимое ревью выявило вложенные reasoning-теги и обработчик, поглощающий
отмену. Ошибки воспроизведены отдельными тестами и исправлены перед полным прогоном.

запись, независимое чтение, замена и двукратное удаление. QA-запись удалена.
Настоящие пользовательские токены не изменялись и не выводились.
Аутентификация с настоящим сервером LM Studio **не проверена**.
Подробности без секретов: [lmstudio-preflight.json](lmstudio-preflight.json).

Реальные обращения к `http://localhost:1234/v1/models`: первоначально отказ
соединения, после сообщения пользователя о запуске — таймаут и при последней
проверке снова недоступность. Фактический ID не получен. Сервер не подменялся
Ollama или фикстурой. [Результат реальной диагностики](lmstudio-real-results.json).

Подготовлен `scripts/qa_lmstudio.py`: при доступном сервере и явно заданном ID
он использует настоящий HTTP, выбранный TTS и QAudioSink, без поддельных
ответов, с нулевой громкостью. Один запуск с новым клиентом отделяется от
20 повторов. Каждый ответ отменяется после первого ActiveState. Статистика:
медиана и линейно интерполированный p95; TTFT — от начала HTTP-запроса до
первого **видимого** текста после фильтра reasoning. Источник запроса — текст,
а не речь; ActiveState не равен акустическому первому звуку. Проба tool calling
перед серией может прогреть модель, поэтому первый запрос серии не выдаётся
за холодную загрузку модели. При недоступности серверa статистика остаётся null.

## Инструменты и ограничения

В текущем репозитории нет существующего исполняемого реестра инструментов.
Есть анализ экрана с обязательным предпросмотром и ограничением Gemini.
Он сохранён. Пользователю отправлен вопрос, какие инструменты подключить;
ответ пока не получен. Реализован и протестирован транспорт tool calling с
явным allowlist `Tool`, но **производственные инструменты не подключены**.
Синтетическая проба в настройках не исполняет действия приложения.

Универсальное отключение thinking через OpenAI-compatible endpoint не
документировано LM Studio. Не передаются предполагаемые JSON-параметры.
Документированный /no_think применяется только к исходному семейству Qwen3;
остальные режимы требуют настройки совместимой модели на сервере.
Непомеченные рассуждения в обычном content нельзя автоматически распознать.
Физические проверки голоса/наушников/динамиков в этой задаче не повторялись;
новых подтверждений устранения известных акустических ограничений нет.

Адаптер и GUI проверены автоматикой; полная проверка интеграции и производственные
инструменты остаются заблокированы отсутствием доступного сервера/выбранной
модели и уточнения списка инструментов. Готовность этих сценариев не заявляется.
